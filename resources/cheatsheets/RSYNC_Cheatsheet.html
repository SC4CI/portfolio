PORT 873 / TCP — RSYNC

rsync — من الفحص إلى ما بعد الاستغلال

Quick Service Reference — مرجع عملي سريع أثناء اللاب لاكتشاف rsync، تعداد الـmodules، اختبار الصلاحيات، والوصول للملفات.

1. Reconnaissance

تأكد من الشبكة والهدف قبل البدء بفحص الخدمة.

معرفة عنوانك ومسارات الشبكة KALI TERMINAL
ip a ip route
اختبار الوصول للهدف KALI TERMINAL
ping -c 4 [TARGET]
عدم الرد على ICMP لا يعني أن الخدمة مغلقة؛ استخدم -Pn مع Nmap.
اكتشاف الأجهزة داخل الشبكة KALI TERMINAL
nmap -sn [SUBNET]

2. Port Scanning

ابدأ بالبورت الافتراضي ثم نفّذ Full Port Scan إذا لزم.

فحص rsync على البورت الافتراضي KALI TERMINAL
nmap -Pn -p873 -sV [TARGET]
GENERAL REFERENCE — النجاح = Nmap يعرّف rsync أو يؤكد الخدمة المتوقعة على البورت.
فحص Scripts + Version KALI TERMINAL
nmap -Pn -p873 -sC -sV [TARGET]
فحص جميع البورتات KALI TERMINAL
nmap -Pn -p- --min-rate 1000 [TARGET]
الفحص السريع قد يكون مزعجًا خارج اللابات؛ استخدمه فقط على بيئة مصرح بها.
إذا ظهر rsync على بورت غير قياسي KALI TERMINAL
nmap -Pn -p[PORT] -sC -sV [TARGET]

3. Enumeration

الهدف الأساسي: معرفة أسماء الـmodules وما إذا كانت تسمح بالقراءة أو الكتابة.

تعداد الـmodules بدون مصادقة KALI TERMINAL
rsync rsync://[TARGET]:[PORT]/
إذا ظهرت أسماء Modules فهذا أهم مدخل للعملية؛ دوّن الأسماء كما هي.
GENERAL REFERENCE — إذا ظهرت Modules بدون credentials فهذا وصول غير موثق إلى قائمة الموارد؛ قيّم كل Module منفصلًا.
طريقة مختصرة بديلة KALI TERMINAL
rsync [TARGET]::
عرض محتويات Module محدد KALI TERMINAL
rsync rsync://[TARGET]:[PORT]/[MODULE]/
عرض Recursive مع تفاصيل أكثر KALI TERMINAL
rsync -av --list-only rsync://[TARGET]:[PORT]/[MODULE]/
استخدم --list-only قبل التنزيل الكامل حتى تعرف حجم ومحتوى الـmodule.
فحص NSE إن كان السكربت متوفرًا KALI TERMINAL
nmap -Pn -p[PORT] --script rsync-list-modules [TARGET]
فحص يدوي للبروتوكول KALI TERMINAL
nc -nv [TARGET] [PORT]
قد يظهر Banner بروتوكول rsync مثل @RSYNCD: مما يؤكد الخدمة.

4. Credential Testing

بعض الـmodules عامة، وبعضها يحتاج مستخدم/كلمة مرور حسب إعداد daemon.

الوصول باستخدام مستخدم محدد KALI TERMINAL
rsync rsync://[USERNAME]@[TARGET]:[PORT]/[MODULE]/
إذا كانت المصادقة مطلوبة سيطلب rsync كلمة المرور تفاعليًا.
GENERAL REFERENCE — النجاح = قبول credentials والسماح بعرض/الوصول إلى الـModule ضمن صلاحيات الحساب.
استخدام ملف كلمة مرور KALI TERMINAL
rsync --password-file=[FILE] rsync://[USERNAME]@[TARGET]:[PORT]/[MODULE]/
ملف كلمة المرور يجب أن تكون صلاحياته ضيقة، وتجنب ترك كلمات المرور مكشوفة في ملفات مشتركة.
البحث عن Modules rsync داخل Metasploit MSFCONSOLE
search type:auxiliary rsync info [RSYNC_MODULE]
لا تستخدم Module عشوائيًا؛ راجع خياراته وما إذا كان مخصصًا للتعداد أو المصادقة.
ضبط الهدف داخل Module مناسب MSFCONSOLE
use [RSYNC_MODULE] show options set RHOSTS [TARGET] set RPORT [PORT] run

5. File Access / Read-Write Assessment

الاستغلال العملي غالبًا يكون بسبب Module مكشوف للقراءة أو الكتابة، وليس بسبب CVE عشوائي.

تنزيل Module كامل للقراءة المحلية KALI TERMINAL
mkdir -p [DIR] rsync -av rsync://[TARGET]:[PORT]/[MODULE]/ [DIR]/
راجع الملفات بحثًا عن configs، مفاتيح، backups، أو بيانات اعتماد قد تكون قابلة لإعادة الاستخدام.
GENERAL REFERENCE — النجاح = تنزيل الملفات التي يسمح الـModule بقراءتها إلى المسار المحلي المحدد.
تنزيل ملف واحد فقط KALI TERMINAL
rsync -av rsync://[TARGET]:[PORT]/[MODULE]/[FILE] ./[FILE]
اختبار الكتابة بملف بسيط KALI TERMINAL
echo "authorized-lab-test" > /tmp/rsync_test.txt rsync -av /tmp/rsync_test.txt rsync://[TARGET]:[PORT]/[MODULE]/
هذا يغيّر بيانات الهدف. نفّذه فقط داخل Lab أو عند وجود تصريح صريح بالكتابة.
التأكد من رفع الملف KALI TERMINAL
rsync -av --list-only rsync://[TARGET]:[PORT]/[MODULE]/
GENERAL REFERENCE — نجاح write test = ظهور test file في الـModule بعد الرفع؛ استخدم cleanup الحالي عندما يكون آمنًا ومسموحًا.
إذا كان الـmodule يطابق مسار Web معروف وقابل للكتابة KALI TERMINAL
rsync -av [FILE] rsync://[TARGET]:[PORT]/[MODULE]/[WEB_PATH]/
استخدم هذا فقط إذا عرفت من الـenumeration أن المسار مرتبط فعلًا بـWeb Root؛ لا تفترض ذلك بدون دليل.
إذا كان الـmodule يطابق Home Directory لمستخدم KALI TERMINAL
rsync -av --list-only rsync://[TARGET]:[PORT]/[MODULE]/.ssh/
الوصول إلى ملفات مفاتيح SSH أو تعديلها عالي التأثير؛ افحصها فقط ضمن النطاق المصرح، ولا تكتب شيئًا إلا إذا كان اللاب يتطلب ذلك.

6. Post-Access / Cleanup / Handoff

بعد الوصول للملفات، حوّل ما وجدته إلى خطوات واضحة بدون تكرار ملفات Post-Exploitation العامة.

البحث عن بيانات اعتماد أو أسرار داخل الملفات المنزلة KALI TERMINAL
grep -RniE "password|passwd|user(name)?|token|secret|key" [DIR]/ 2>/dev/null
البحث عن مفاتيح SSH KALI TERMINAL
find [DIR] -type f \( -name "id_rsa" -o -name "id_ed25519" -o -name "*.pem" \) 2>/dev/null
مراجعة ملفات الإعداد الشائعة KALI TERMINAL
find [DIR] -type f \( -name "*.conf" -o -name "*.ini" -o -name "*.env" -o -name "*.yml" -o -name "*.yaml" \) 2>/dev/null
إعادة فحص الخدمات بعد اكتشاف Hostnames أو IPs جديدة KALI TERMINAL
nmap -Pn -sV [DISCOVERED_TARGET]
أي credentials أو hosts تكتشفها هنا تُعاد للاستفادة منها في ملفات SSH/SMB/Web أو Pivoting المنفصلة.
تنظيف ملف الاختبار إذا كان مسموحًا وآمنًا KALI TERMINAL
rsync --delete -av /tmp/empty_dir/ rsync://[TARGET]:[PORT]/[MODULE]/
لا تستخدم --delete على Module حقيقي بهذه الصورة إلا إذا كنت متأكدًا 100% من الهدف؛ قد يحذف ملفات كثيرة. الأفضل حذف ملف الاختبار من داخل البيئة إذا كانت لديك جلسة شرعية.
