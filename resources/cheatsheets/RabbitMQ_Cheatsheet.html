1. Reconnaissance

حدد الهدف والواجهة والوصول قبل لمس RabbitMQ

معرفة الـIP والواجهة المستخدمة KALI TERMINAL
ip a ifconfig
حدد واجهة اللاب أو الـVPN قبل أي اتصال بالخدمة.
التأكد من الوصول للهدف KALI TERMINAL
ping -c 4 [TARGET]
إذا ICMP محجوب لا تعتبر الهدف Down؛ انتقل مباشرة للفحص بـNmap.
اكتشاف الأجهزة إذا الهدف غير معروف KALI TERMINAL
nmap -sn [SUBNET] netdiscover -r [SUBNET]
RabbitMQ غالبًا يظهر كجزء من تطبيق Backend؛ سجّل أي Web/API services على نفس الجهاز لأنها قد تقودك لبيانات RabbitMQ.

2. Port Scanning

اكتشف AMQP وواجهة الإدارة ولا تعتمد على البورت الافتراضي فقط

فحص البورتين الأساسيين KALI TERMINAL
nmap -sS -sV -p5672,15672 [TARGET]
5672/tcp open amqp 15672/tcp open http
5672 = AMQP client traffic، و15672 = Management HTTP UI/API إذا كانت مفعلة.
فحص شامل إذا ما ظهرت الخدمة KALI TERMINAL
nmap -p- --min-rate=1000 -T4 [TARGET]
لا تستبعد RabbitMQ فقط لأن 5672/15672 مقفلة؛ قد تكون الخدمة على بورت غير قياسي.
فحص مركز للخدمات المكتشفة KALI TERMINAL
nmap -p5672,15672 -sV -sC [TARGET]
لو اكتشفت بورتات مختلفة، استبدل الأرقام في الخطوات التالية بالبورتات الفعلية.

3. Enumeration

أكد البروتوكول وافصل بين AMQP 5672 وManagement HTTP 15672

AMQP / Service Detection

فحص AMQP عبر Nmap NSE KALI TERMINAL
nmap -p5672 --script amqp-info [TARGET]
يفيد في تأكيد بروتوكول AMQP وجمع خصائص يعرضها الـbroker بدون افتراض نسخة محددة.
Banner / handshake سريع KALI TERMINAL
nc -nv [TARGET] 5672
AMQP بروتوكول binary؛ عدم ظهور banner نصي طبيعي. استخدم Nmap أو client فعلي للتأكيد.

Management Interface — 15672

فتح واجهة الإدارة BROWSER
http://[TARGET]:15672/
RabbitMQ Management login page
إذا ظهرت صفحة RabbitMQ Management صار عندك سطح HTTP/API منفصل عن AMQP.
فحص Headers والواجهة KALI TERMINAL
curl -i http://[TARGET]:15672/
سجّل Status Code وWWW-Authenticate وأي معلومات إصدار تظهر فعليًا.
اختبار API بدون Credentials KALI TERMINAL
curl -i http://[TARGET]:15672/api/overview
HTTP/1.1 401 Unauthorized
401 يعني الـManagement API موجود لكنه يطلب Authentication.
فحص HTTP بـNmap KALI TERMINAL
nmap -p15672 --script http-title,http-headers [TARGET]
طريقة بديلة لتأكيد صفحة الإدارة وجمع الـheaders بدون تسجيل دخول.

4. Credential Testing

تحقق من Authentication بشكل قابل للقياس قبل أي خطوة لاحقة

اختبار Credentials معروفة

اختبار حساب على Management API KALI TERMINAL
curl -i -u [USERNAME]:[PASSWORD] http://[TARGET]:15672/api/overview
HTTP/1.1 200 OK
200 مع JSON يعني بيانات الدخول صحيحة ولديك وصول للـManagement API.
اختبار الدخول من المتصفح BROWSER
http://[TARGET]:15672/
استخدم فقط Credentials حصلت عليها من اللاب/التطبيق/ملفات الإعداد أو بيانات مصرح باختبارها.

Password Testing

Hydra على HTTP Basic للـManagement API KALI TERMINAL
hydra -L [USERLIST] -P [WORDLIST] [TARGET] -s 15672 http-get /api/overview
استخدمه فقط إذا كان endpoint يعيد 401 للفشل و200 للنجاح؛ تحقق يدويًا أولًا.
اختبار قائمة Credentials بطريقة HTTP مباشرة KALI TERMINAL
curl -s -o /dev/null -w '%{http_code}\n' -u [USERNAME]:[PASSWORD] http://[TARGET]:15672/api/overview
مفيد للتحقق من Credential واحدة بدون الاعتماد على واجهة المتصفح.
تنبيه: حساب guest في RabbitMQ يكون افتراضيًا مقيّدًا عادةً بالاتصال المحلي. لا تفترض أن guest:guest سيعمل عن بعد، ولا تعتبر فشله دليلًا أن الخدمة غير قابلة للدخول.

5. Authenticated API / Permission Assessment

استفد من الوصول الموثق والصلاحيات الفعلية بدل تشغيل Exploit عشوائي

Authenticated Management Access

عرض معلومات الـBroker KALI TERMINAL
curl -s -u [USERNAME]:[PASSWORD] http://[TARGET]:15672/api/overview
راجع النسخة، cluster name، وإحصاءات الخدمة التي يعيدها الحساب فعليًا.
عرض Virtual Hosts KALI TERMINAL
curl -s -u [USERNAME]:[PASSWORD] http://[TARGET]:15672/api/vhosts
الـvhost يحدد namespace للـexchanges والqueues والصلاحيات.
عرض Queues KALI TERMINAL
curl -s -u [USERNAME]:[PASSWORD] http://[TARGET]:15672/api/queues
سجّل أسماء الـqueues والـvhost وعدد الرسائل فقط ضمن صلاحيات الحساب.
عرض Exchanges KALI TERMINAL
curl -s -u [USERNAME]:[PASSWORD] http://[TARGET]:15672/api/exchanges
يساعدك تفهم مسار الرسائل والـrouting داخل البيئة.
عرض المستخدمين إذا الحساب يسمح KALI TERMINAL
curl -s -u [USERNAME]:[PASSWORD] http://[TARGET]:15672/api/users
نجاح هذا الطلب يدل على صلاحيات إدارية أعلى من مجرد قراءة queue.
عرض Permissions KALI TERMINAL
curl -s -u [USERNAME]:[PASSWORD] http://[TARGET]:15672/api/permissions
حدد بالضبط أي vhost وconfigure/write/read permissions يملكها الحساب.
قبل أي Exploitation: تأكد من النسخة، صلاحيات الحساب، الـvhost والـpreconditions. لا تستخدم CVE أو مسار تنفيذ عشوائي لمجرد أن RabbitMQ ظاهر؛ لا توجد هنا نتيجة Lab ثابتة لـRabbitMQ exploit محدد.

6. Evidence / Handoff

ثبّت ما وصلت له واجمع المعلومات الفورية بدون تغيير أو تخريب الخدمة

تأكيد مستوى الوصول KALI TERMINAL
curl -s -u [USERNAME]:[PASSWORD] http://[TARGET]:15672/api/whoami
ثبت اسم المستخدم والـtags الفعلية قبل الانتقال لأي خطوة أخرى.
حفظ Overview للمراجعة KALI TERMINAL
curl -s -u [USERNAME]:[PASSWORD] http://[TARGET]:15672/api/overview -o rabbitmq_overview.json
يحفظ معلومات الجلسة محليًا بدون تعديل الـbroker.
حفظ قائمة الـQueues KALI TERMINAL
curl -s -u [USERNAME]:[PASSWORD] http://[TARGET]:15672/api/queues -o rabbitmq_queues.json
راجع أسماء الـqueues والرسائل المتاحة ضمن نطاق اللاب، ولا تنفذ عمليات حذف أو purge.
التحقق من صلاحيات الحساب KALI TERMINAL
curl -s -u [USERNAME]:[PASSWORD] http://[TARGET]:15672/api/permissions
بعد إثبات الوصول، اربط النتائج بالتطبيق الذي يستخدم RabbitMQ وابحث عن credential reuse أو secrets في المسارات المصرح بها بدل القفز مباشرة لاستغلال غير موثق.
