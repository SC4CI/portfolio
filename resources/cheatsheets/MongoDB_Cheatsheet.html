1. Reconnaissance

ثبّت نطاق اللاب وحدد الهدف والشبكة قبل فحص MongoDB.

معرفة عنوانك وواجهات الشبكة KALI TERMINAL
ip a
عرض الشبكات والمسارات KALI TERMINAL
ip route
اختبار استجابة الهدف KALI TERMINAL
ping -c 4 [TARGET]
إذا ICMP محجوب استخدم Nmap بخيار -Pn.
اكتشاف الأجهزة داخل الشبكة عند الحاجة KALI TERMINAL
nmap -sn [SUBNET]

2. Port Scanning

MongoDB يستخدم 27017/TCP افتراضيًا، لكن قد يعمل على بورت مخصص.

فحص البورت الافتراضي وتحديد الخدمة KALI TERMINAL
nmap -Pn -p27017 -sV [TARGET]
GENERAL REFERENCE — النجاح = Nmap يعرّف MongoDB أو يؤكد الخدمة المتوقعة على البورت.
تشغيل Default Scripts مع Version Detection KALI TERMINAL
nmap -Pn -p27017 -sC -sV [TARGET]
فحص كل TCP ports KALI TERMINAL
nmap -Pn -p- --min-rate 1000 [TARGET]
الفحص الكامل السريع مخصص للاب/النطاق المصرح فقط.
إعادة فحص البورت المكتشف غير القياسي KALI TERMINAL
nmap -Pn -p[PORT] -sC -sV [TARGET]

3. Enumeration

حدد الإصدار، حالة المصادقة، قواعد البيانات، والمجموعات قبل أي اختبار كتابة.

Nmap NSE

معلومات MongoDB KALI TERMINAL
nmap -Pn -p[PORT] --script mongodb-info [TARGET]
محاولة تعداد قواعد البيانات KALI TERMINAL
nmap -Pn -p[PORT] --script mongodb-databases [TARGET]
السكربت قد يفشل إذا كانت المصادقة مطلوبة، وهذا بحد ذاته مؤشر مفيد.

mongosh

اتصال مباشر بدون بيانات اعتماد KALI TERMINAL
mongosh --host [TARGET] --port [PORT]
GENERAL REFERENCE — إذا فتح الاتصال وسمح بالاستعلام بدون credentials فهذا وصول غير موثق.
عرض قواعد البيانات MONGOSH
show dbs
GENERAL REFERENCE — النجاح = ظهور Databases التي يسمح السياق الحالي برؤيتها.
عرض قاعدة البيانات الحالية MONGOSH
db
اختيار قاعدة MONGOSH
use [DATABASE]
عرض Collections MONGOSH
show collections
قراءة عينة من Collection MONGOSH
db.[COLLECTION].find().limit(10)
عرض Stats للقاعدة MONGOSH
db.stats()
عرض معلومات الخادم MONGOSH
db.adminCommand({ buildInfo: 1 })
البحث عن Modules داخل Metasploit MSFCONSOLE
search mongodb search type:auxiliary mongodb
استخدم info [MODULE] وshow options قبل التشغيل.

4. Credential Testing

اختبر بيانات الاعتماد المعروفة أولًا، مع الانتباه إلى authSource.

اتصال باسم مستخدم وكلمة مرور KALI TERMINAL
mongosh "mongodb://[USERNAME]:[PASSWORD]@[TARGET]:[PORT]/?authSource=admin"
GENERAL REFERENCE — النجاح = قبول credentials وفتح session تسمح بالاستعلام ضمن صلاحيات الحساب.
اتصال مع authSource مخصص KALI TERMINAL
mongosh "mongodb://[USERNAME]:[PASSWORD]@[TARGET]:[PORT]/[DATABASE]?authSource=[AUTH_DB]"
التحقق من المستخدم الحالي MONGOSH
db.runCommand({ connectionStatus: 1 })
عرض المستخدمين داخل قاعدة مخولة MONGOSH
db.getUsers()
يعتمد على صلاحيات الحساب؛ قد يُرفض إذا لم تكن لديك privileges كافية.
اختبار URI عبر Metasploit بعد العثور على Module مناسب MSFCONSOLE
search mongodb login info [MONGODB_LOGIN_MODULE] use [MONGODB_LOGIN_MODULE] show options
اختبارات كلمات المرور قد تكون noisy؛ استخدم فقط بيانات/قوائم صغيرة مصرح بها داخل اللاب.

5. Database Access / Read-Write Assessment

المسار العملي الأهم هو سوء إعداد MongoDB المكشوف: قراءة البيانات أو إثبات صلاحية الكتابة بدون تدمير بيانات حقيقية.

Unauthenticated / Over-Privileged Data Access

قراءة أول 20 سجلًا MONGOSH
db.[COLLECTION].find().limit(20)
عرض أسماء الحقول من أول سجل MONGOSH
Object.keys(db.[COLLECTION].findOne() || {})
البحث عن قيمة محددة MONGOSH
db.[COLLECTION].find({ "[FIELD]": "[VALUE]" }).limit(20)
عدّ السجلات MONGOSH
db.[COLLECTION].countDocuments({})

إثبات الكتابة بشكل آمن

إنشاء قاعدة/Collection اختبارية MONGOSH
use ejpt_test
هذا يغيّر حالة الهدف؛ نفذه فقط إذا اللاب يسمح بإثبات write access.
إضافة Document تجريبي MONGOSH
db.proof.insertOne({ proof: "authorized-lab" })
قراءة الـDocument التجريبي MONGOSH
db.proof.find()
GENERAL REFERENCE — نجاح write test = ظهور الـtest document بعد إنشائه؛ استخدم خطوات الحذف الحالية للتنظيف.
حذف الـCollection التجريبية MONGOSH
db.proof.drop()
تأكد أنك داخل قاعدة ejpt_test فقط قبل الحذف.
حذف قاعدة الاختبار عند الانتهاء MONGOSH
db.dropDatabase()
أمر مدمّر. لا تنفذه إلا وأنت متأكد 100% أن قاعدة البيانات الحالية هي قاعدة الاختبار التي أنشأتها.

Version-Specific Assessment

البحث عن Exploit مطابق بعد معرفة النسخة MSFCONSOLE
search mongodb info [MATCHED_EXPLOIT]
لا تشغّل أي exploit بدون مطابقة واضحة للإصدار والـpreconditions.

6. Evidence / Handoff

احفظ المعلومات المهمة وحدد الخدمات/البيانات الجديدة التي تقودك للخطوة التالية.

حفظ أسماء قواعد البيانات يدويًا KALI TERMINAL
mongosh --quiet --host [TARGET] --port [PORT] --eval 'db.adminCommand({listDatabases:1}).databases.forEach(d=>print(d.name))' > mongo_databases.txt
حفظ قائمة Collections KALI TERMINAL
mongosh --quiet --host [TARGET] --port [PORT] [DATABASE] --eval 'db.getCollectionNames().forEach(print)' > mongo_collections.txt
البحث في ملفات النتائج عن Hosts/IPs KALI TERMINAL
grep -Eo '([0-9]{1,3}\.){3}[0-9]{1,3}' mongo_databases.txt mongo_collections.txt | sort -u
فحص أي منافذ/خدمات جديدة اكتشفتها KALI TERMINAL
nmap -Pn -sV -p[DISCOVERED_PORTS] [TARGET]
إذا حصلت لاحقًا على Shell: تحديد المستخدم VICTIM SHELL
whoami
إذا حصلت لاحقًا على Shell: معلومات النظام VICTIM SHELL
id hostname uname -a
بعد Shell انتقل لملف Linux/Windows Post-Exploitation المخصص بدل تكرار كل شيء هنا.
