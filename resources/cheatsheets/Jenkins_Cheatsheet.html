1. Reconnaissance

ثبت الهدف وافتح واجهة الويب المحتملة قبل التعمق.

معرفة عنوانك وواجهة اللاب KALI TERMINAL
ip a ip route
حدد واجهة الـVPN/اللاب ومسار الشبكة قبل الفحص.
اختبار الوصول للهدف KALI TERMINAL
ping -c 4 [TARGET]
إذا ICMP محجوب، استخدم -Pn في Nmap ولا تعتبر الهدف Down.
فتح واجهة Jenkins المحتملة BROWSER
http://[TARGET]:8080 https://[TARGET]:[PORT]
لاحظ هل تظهر Jenkins Dashboard أو صفحة Login أو Redirect لمسار مختلف.

2. Port Scanning

ابدأ بـ8080/50000 ثم وسع الفحص إذا كانت الخدمة على بورت غير قياسي.

فحص Jenkins الشائع على 8080 KALI TERMINAL
nmap -Pn -p8080 -sV [TARGET]
8080/TCP شائع لواجهة Jenkins، لكنه ليس إلزاميًا.
فحص Web + Agent Ports الشائعة KALI TERMINAL
nmap -Pn -p8080,50000 -sC -sV [TARGET]
50000/TCP قد يُستخدم لاتصالات Jenkins agents حسب الإعداد.
فحص HTTP Scripts على البورت المكتشف KALI TERMINAL
nmap -Pn -p[PORT] --script=http-title,http-headers,http-methods [TARGET]
العنوان والـheaders قد يكشفان Jenkins أو reverse proxy أمامه.
Full TCP Scan إذا لم يظهر على البورتات الشائعة KALI TERMINAL
nmap -Pn -p- --min-rate 1000 [TARGET]
استخدم معدل الفحص المناسب فقط داخل Lab أو حسب قواعد الاختبار المصرح.
إعادة الفحص على البورت الفعلي KALI TERMINAL
nmap -Pn -p[PORT] -sC -sV [TARGET]

3. Enumeration

حدد هل التطبيق Jenkins فعلًا، وما الذي يسمح به Anonymous Access قبل اختبار الحسابات.

Fingerprinting

فحص الصفحة والـRedirects KALI TERMINAL
curl -i http://[TARGET]:[PORT]/
راجع Status Code وLocation وServer headers وأي Jenkins-specific headers إن ظهرت.
WhatWeb KALI TERMINAL
whatweb http://[TARGET]:[PORT]
استخدمه كطبقة Fingerprinting إضافية، وليس كإثبات وحيد للإصدار.
Metasploit HTTP Version Scanner MSFCONSOLE
use auxiliary/scanner/http/http_version set RHOSTS [TARGET] set RPORT [PORT] run

Jenkins-specific Checks

فحص صفحة Login BROWSER
http://[TARGET]:[PORT]/login
إذا ظهرت صفحة Jenkins Login فهذا يؤكد مسار المصادقة، لكن لا يفترض وجود بيانات دخول افتراضية.
فحص API العام بحذر KALI TERMINAL
curl -i http://[TARGET]:[PORT]/api/json
إذا كان Anonymous Read مسموحًا قد ترجع Metadata؛ 401/403 يعني أن الوصول مقيد.
فحص صفحة Manage Jenkins BROWSER
http://[TARGET]:[PORT]/manage
الوصول يعتمد على الصلاحيات. لا تعتبر ظهور الرابط دليلًا على صلاحية إدارية.
البحث عن Jenkins Modules بدل تخمين الاسم MSFCONSOLE
search jenkins search type:auxiliary jenkins search type:exploit jenkins
أسماء Modules تختلف حسب إصدار Metasploit. استخدم info [MODULE] وshow options قبل أي تشغيل.
لا توجد هنا نتيجة Jenkins Lab أو Expected Output ثابتة؛ لذلك لا نخترع Version أو Username أو مسارًا ناجحًا.

4. Credential Testing

استخدم Credentials معروفة أو Scanner مصرح فقط، ولا تخترع Default Credentials.

اختبار Credentials معروفة عبر الواجهة BROWSER
http://[TARGET]:[PORT]/login
استخدم فقط Credentials حصلت عليها من اللاب أو من مسار مصرح.
التحقق من Authentication بالـAPI KALI TERMINAL
curl -i -u '[USERNAME]:[PASSWORD]' http://[TARGET]:[PORT]/api/json
نجاح HTTP Authentication والوصول للـAPI يؤكد أن البيانات صالحة وفق صلاحيات الحساب.
البحث عن Jenkins Login Scanner MSFCONSOLE
search jenkins login search type:auxiliary jenkins
اختر Scanner المتاح فعليًا في نسختك بدل افتراض اسم Module ثابت.
مراجعة خيارات Scanner قبل التشغيل MSFCONSOLE
info [JENKINS_LOGIN_MODULE] use [JENKINS_LOGIN_MODULE] show options
Password spraying/brute force قد يسبب Lockout أو ضوضاء. شغله فقط إذا كان جزءًا صريحًا من Lab/Scope.
لا تفترض وجود أي Default Credentials. اعتمد فقط على بيانات ظهرت فعليًا في اللاب أو مصدر مصرح.

5. Exploitation

ركز على Misconfiguration أو وصول إداري مصرح، وتحقق بشكل غير تخريبي قبل أي مسار استغلال.

Authorized Administrative Execution

التحقق من Script Console بعد Login BROWSER
http://[TARGET]:[PORT]/script
إذا كان الحساب مخولًا إداريًا قد تظهر Script Console. مجرد 403/404 لا يثبت ثغرة أو غياب Jenkins.
اختبار غير تخريبي داخل Script Console JENKINS SCRIPT CONSOLE
println System.getProperty('os.name') println System.getProperty('user.name')
يرجع اسم نظام التشغيل والمستخدم الذي تعمل به عملية Jenkins إذا كانت الصلاحية تسمح.
هذا Proof غير تخريبي على القدرة على تنفيذ Groovy داخل Jenkins بدون إنشاء Reverse Shell.
البحث عن Exploit Modules المناسبة MSFCONSOLE
search jenkins info [MODULE] show options check
لا تستخدم exploit لمجرد أن Jenkins ظاهر. طابق Version/Auth/Permissions/Preconditions أولًا، واستخدم check إذا كان الـModule يدعمه.
تحذير: Script Console بحد ذاتها وظيفة إدارية وليست ثغرة إذا كانت محمية بشكل صحيح. الخطر يكون عند وصول غير مصرح أو Credentials ضعيفة/مسروقة أو Misconfiguration.

6. Post-Exploitation

وثّق السياق واربط Jenkins بالخدمات الأخرى بدون تكرار مواضيع Post-Exploitation العامة.

تأكيد هوية Jenkins Runtime بدون تغيير النظام JENKINS SCRIPT CONSOLE
println System.getProperty('user.name') println System.getProperty('java.version') println System.getProperty('os.name')
سجّل السياق الفعلي فقط إذا كانت لديك صلاحية Script Console ضمن اللاب.
حفظ Fingerprint محليًا KALI TERMINAL
curl -i http://[TARGET]:[PORT]/ > jenkins_http.txt nmap -Pn -p[PORT] -sV [TARGET] -oN jenkins_service.txt
يحفظ Evidence محليًا بدون تعديل Jenkins.
ربط Jenkins بالخدمات الأخرى KALI TERMINAL
nmap -Pn -sV [TARGET]
إذا كشف Jenkins Hostnames أو URLs أو Credentials ضمن Lab مصرح، انتقل إلى Cheatsheet الخدمة المرتبطة بدل تكرار Post-Exploitation العام.
لا نكرر Credential Dumping أو Pivoting أو Meterpreter العامة هنا؛ هذه لها مراجع مستقلة في المشروع.
