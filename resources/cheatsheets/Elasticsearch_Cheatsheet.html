1. Reconnaissance

ثبّت نطاق اللاب وحدد عنوانك والشبكة والهدف قبل أي فحص.

معرفة عنوانك وواجهات الشبكة KALI TERMINAL
ip a
داخل لابات VPN ركّز على واجهة مثل tun0.
عرض الـRoutes والشبكات المتاحة KALI TERMINAL
ip route
اختبار استجابة الهدف KALI TERMINAL
ping -c 4 [TARGET]
عدم الرد لا يعني أن الخدمة غير موجودة؛ استخدم -Pn مع Nmap.
اكتشاف الأجهزة عند الحاجة KALI TERMINAL
nmap -sn [SUBNET]

2. Port Scanning

Elasticsearch REST API يظهر غالبًا على 9200/TCP، وTransport غالبًا على 9300/TCP.

فحص 9200 مع Version Detection KALI TERMINAL
nmap -Pn -p9200 -sV [TARGET]
GENERAL REFERENCE — النجاح = Nmap يعرّف Elasticsearch/HTTP أو يؤكد الخدمة المتوقعة على البورت.
فحص REST + Transport KALI TERMINAL
nmap -Pn -p9200,9300 -sC -sV [TARGET]
فحص كل بورتات TCP KALI TERMINAL
nmap -Pn -p- --min-rate 1000 [TARGET]
الفحص الكامل السريع قد يكون مزعجًا خارج اللابات؛ استخدمه فقط في نطاق مصرح.
إعادة فحص البورت المكتشف غير القياسي KALI TERMINAL
nmap -Pn -p[PORT] -sC -sV [TARGET]

3. Enumeration

حدد النسخة، اسم الـCluster/Node، حالة الـAPI، الـIndices، وما إذا كانت الحماية مفعلة.

REST API مباشرة

طلب الصفحة الجذرية KALI TERMINAL
curl -i http://[TARGET]:[PORT]/
الاستجابة قد تكشف اسم الـnode والـcluster ورقم الإصدار إذا كانت الواجهة متاحة بدون مصادقة.
GENERAL REFERENCE — إذا رجعت معلومات cluster/node بدون credentials فهذا وصول غير موثق ويجب تقييم نطاق البيانات المكشوفة.
معلومات الـCluster KALI TERMINAL
curl -s http://[TARGET]:[PORT]/_cluster/health?pretty
معلومات الـNodes KALI TERMINAL
curl -s http://[TARGET]:[PORT]/_nodes?pretty
قائمة الـIndices KALI TERMINAL
curl -s http://[TARGET]:[PORT]/_cat/indices?v
GENERAL REFERENCE — النجاح = ظهور أسماء Indices التي يسمح السياق الحالي برؤيتها.
قائمة الـNodes المختصرة KALI TERMINAL
curl -s http://[TARGET]:[PORT]/_cat/nodes?v
قائمة الـAliases KALI TERMINAL
curl -s http://[TARGET]:[PORT]/_cat/aliases?v
عرض الـMappings لكل الـIndices KALI TERMINAL
curl -s http://[TARGET]:[PORT]/_mapping?pretty
عرض إعدادات الـIndices KALI TERMINAL
curl -s http://[TARGET]:[PORT]/_settings?pretty

Nmap / Metasploit

فحص HTTP headers والعنوان KALI TERMINAL
nmap -Pn -p[PORT] --script http-headers,http-title [TARGET]
البحث عن Modules مرتبطة بـElasticsearch MSFCONSOLE
search elasticsearch search type:auxiliary elasticsearch
استخدم info [MODULE] قبل التشغيل ولا تفترض أن أي Module يناسب نسختك.

4. Credential Testing

Elasticsearch الحديث قد يستخدم Basic Auth/TLS عبر Elastic Security؛ اختبر بيانات معروفة أولًا بدل افتراض عدم وجود حماية.

اختبار بيانات اعتماد معروفة عبر Basic Auth KALI TERMINAL
curl -i -u [USERNAME]:[PASSWORD] http://[TARGET]:[PORT]/
GENERAL REFERENCE — النجاح = قبول credentials وإرجاع مورد محمي بدل رفض المصادقة.
اختبار نفس البيانات على Cluster Health KALI TERMINAL
curl -s -u [USERNAME]:[PASSWORD] http://[TARGET]:[PORT]/_cluster/health?pretty
اختبار HTTPS إذا كانت الخدمة تستخدم TLS KALI TERMINAL
curl -k -i -u [USERNAME]:[PASSWORD] https://[TARGET]:[PORT]/
استخدم -k فقط داخل اللاب عند وجود شهادة self-signed.
فحص طريقة المصادقة من الـHeaders KALI TERMINAL
curl -I http://[TARGET]:[PORT]/
اختبار يدوي من Burp عند وجود Reverse Proxy BURP SUITE
GET / HTTP/1.1 Host: [TARGET]:[PORT] Authorization: Basic [BASE64_USER_PASS]
اختبارات كلمات المرور قد تسبب Rate Limiting أو تنبيهات؛ استخدم بيانات لاب معروفة أو قوائم صغيرة مصرح بها.
مراجعة Modules Login/HTTP المطابقة MSFCONSOLE
search elasticsearch login search http_login info [MATCHED_MODULE] show options
لا تستخدم Module عام إلا إذا كان endpoint وطريقة المصادقة مطابقين فعليًا.

5. API Access / Read-Write Assessment

أهم مسار عملي هو إساءة إعداد REST API المكشوفة: قراءة بيانات أو إثبات صلاحية كتابة بشكل غير تدميري داخل اللاب.

Unauthenticated Data Access

قراءة أول سجلات من Index معروف KALI TERMINAL
curl -s "http://[TARGET]:[PORT]/[INDEX]/_search?size=10&pretty"
استعلام Match All KALI TERMINAL
curl -s -H "Content-Type: application/json" -X GET http://[TARGET]:[PORT]/[INDEX]/_search -d '{"query":{"match_all":{}},"size":10}'
عرض أسماء الحقول من Mapping KALI TERMINAL
curl -s http://[TARGET]:[PORT]/[INDEX]/_mapping?pretty
البحث داخل Index عن كلمة محددة KALI TERMINAL
curl -s -H "Content-Type: application/json" -X GET http://[TARGET]:[PORT]/[INDEX]/_search -d '{"query":{"query_string":{"query":"[SEARCH_TERM]"}}}'

إثبات الكتابة بشكل آمن

إنشاء Index تجريبي فقط إذا اللاب يسمح KALI TERMINAL
curl -s -X PUT http://[TARGET]:[PORT]/ejpt_test
هذا يغيّر حالة الهدف. نفّذه فقط إذا اللاب يطلب إثبات write access. لا تستخدم Index موجودًا.
إضافة Document تجريبي KALI TERMINAL
curl -s -H "Content-Type: application/json" -X POST http://[TARGET]:[PORT]/ejpt_test/_doc -d '{"proof":"authorized-lab"}'
استخدم بيانات تجريبية فقط ولا تعدّل بيانات حقيقية.
قراءة الـIndex التجريبي للتأكد KALI TERMINAL
curl -s http://[TARGET]:[PORT]/ejpt_test/_search?pretty
GENERAL REFERENCE — نجاح write test = ظهور الـtest object بعد إنشائه؛ استخدم خطوة الحذف الحالية لتنظيفه.
حذف الـIndex التجريبي بعد الانتهاء KALI TERMINAL
curl -s -X DELETE http://[TARGET]:[PORT]/ejpt_test
الحذف عملية مدمرة؛ تأكد حرفيًا أن الاسم هو الـIndex التجريبي الذي أنشأته أنت.

Version-Specific Exploits

البحث عن Exploit مطابق بعد معرفة النسخة MSFCONSOLE
search elasticsearch info [MATCHED_EXPLOIT]
لا تستخدم Exploit فقط لأن الخدمة Elasticsearch؛ تحقق من الإصدار والـpreconditions أولًا.
عرض خيارات الـExploit بدون تشغيله MSFCONSOLE
use [MATCHED_EXPLOIT] show options
إذا لم توجد مطابقة واضحة للنسخة والإعداد، توقف عند misconfiguration/data exposure بدل تشغيل Exploit عشوائي.

6. Evidence / Handoff

بعد إثبات الوصول، اجمع أقل قدر لازم من المعلومات وحدد الخطوة التالية دون تكرار أوامر Post-Exploitation العامة.

حفظ قائمة الـIndices محليًا KALI TERMINAL
curl -s http://[TARGET]:[PORT]/_cat/indices?v > elastic_indices.txt
حفظ معلومات الـCluster KALI TERMINAL
curl -s http://[TARGET]:[PORT]/_cluster/health?pretty > cluster_health.json
حفظ معلومات الـNodes KALI TERMINAL
curl -s http://[TARGET]:[PORT]/_nodes?pretty > nodes.json
استخراج أسماء الـIndices فقط KALI TERMINAL
curl -s http://[TARGET]:[PORT]/_cat/indices?h=index | sort -u
البحث داخل الملفات المحفوظة عن Hosts/URLs KALI TERMINAL
grep -Eio 'https?://[^\" ]+|([0-9]{1,3}\.){3}[0-9]{1,3}' nodes.json elastic_indices.txt | sort -u
فحص أي خدمة جديدة اكتشفتها KALI TERMINAL
nmap -Pn -sV -p[DISCOVERED_PORTS] [TARGET]
إذا تحولت الثغرة لاحقًا إلى Shell: تحديد الهوية VICTIM SHELL
whoami id hostname
بعد الحصول على Shell انتقل لملف Linux أو Windows Post-Exploitation المخصص بدل حشر كل شيء هنا.
