PORT 389 / TCP-UDP · 636 / TCP — LDAP / LDAPS

LDAP / LDAPS — من الفحص إلى ما بعد الاستغلال

مرجع عملي سريع للـLab: اكتشاف LDAP، RootDSE، Anonymous/Authenticated Bind، Enumeration ثم تحويل النتائج للمسار التالي.

✒ Abdullah Nasser Almsan — Personal Pentest Reference
ملاحظة عن البورت: LDAP يستخدم غالبًا 389/TCP و389/UDP، وLDAPS يستخدم غالبًا 636/TCP. قد تعمل الخدمة على بورت مختلف، لذلك لا تستبعدها قبل الفحص الشامل.

1. Reconnaissance

ثبّت عنوانك ومسار الشبكة والهدف قبل ما تبدأ فحص LDAP.

معرفة عنوان جهازك والواجهات KALI TERMINAL
ip a ip route
في اللاب ركّز على واجهة الـVPN أو الواجهة التي توصلك لشبكة الهدف.
اختبار الوصول للهدف KALI TERMINAL
ping -c 4 [TARGET]
عدم رد ICMP لا يعني أن LDAP مقفل؛ إذا ما رد كمل الفحص باستخدام Nmap مع -Pn.
اكتشاف الأجهزة إذا عندك Subnet فقط KALI TERMINAL
nmap -sn [SUBNET]
إذا كان عندك TARGET جاهز، لا تضيع وقتك في اكتشاف الشبكة كاملة.

2. Port Scanning

ابحث عن LDAP/LDAPS وحدد هل الخدمة مكشوفة على 389 أو 636 أو بورت غير قياسي.

فحص البورتات الافتراضية KALI TERMINAL
nmap -Pn -p389,636 -sV [TARGET]
389/TCP غالبًا LDAP، و636/TCP غالبًا LDAPS.
GENERAL REFERENCE — النجاح = Nmap يعرّف LDAP/LDAPS أو يؤكد البروتوكول المتوقع على البورت.
Default scripts مع تحديد الإصدار KALI TERMINAL
nmap -Pn -p389,636 -sC -sV [TARGET]
قد تظهر معلومات TLS أو Naming Contexts حسب إعداد الخادم.
فحص شامل إذا ما ظهرت الخدمة KALI TERMINAL
nmap -Pn -p- --min-rate 1000 [TARGET]
الفحص السريع بكثافة عالية مناسب للـLab؛ في بيئة حقيقية التزم بنطاق وقواعد الاختبار.
فحص LDAP على بورت مكتشف غير قياسي KALI TERMINAL
nmap -Pn -p[PORT] -sV -sC [TARGET]
إذا ظهر LDAP على بورت مختلف، استخدم [PORT] في الخطوات التالية بدل افتراض 389.

3. Enumeration

ابدأ بـRootDSE لاستخراج Base DN، ثم اختبر Anonymous Bind وعدّد Objects المتاحة.

RootDSE وBase DN

قراءة RootDSE بدون Credentials KALI TERMINAL
ldapsearch -x -H ldap://[TARGET]:389 -s base -b "" namingContexts defaultNamingContext rootDomainNamingContext
إذا ظهر namingContexts أو defaultNamingContext خزّن القيمة كـ[BASE_DN]، مثال عام: DC=example,DC=local.
GENERAL REFERENCE — إذا رجعت naming contexts بدون credentials فهذا anonymous/unauthenticated directory exposure على هذا المستوى.
RootDSE عبر Nmap NSE KALI TERMINAL
nmap -Pn -p389 --script ldap-rootdse [TARGET]
طريقة بديلة سريعة لاستخراج معلومات RootDSE.

Anonymous Bind

اختبار Anonymous Search KALI TERMINAL
ldapsearch -x -H ldap://[TARGET]:389 -b "[BASE_DN]" "(objectClass=*)" dn
إذا رجعت Entries بدون -D/-w فهذا يعني أن الخادم يسمح بقدر من القراءة المجهولة.
GENERAL REFERENCE — النجاح = رجوع DNs/objects بدون bind credentials؛ قيّم نطاق ما يمكن قراءته.
البحث عن Users KALI TERMINAL
ldapsearch -x -H ldap://[TARGET]:389 -b "[BASE_DN]" "(objectClass=user)" sAMAccountName userPrincipalName
في Active Directory ركّز على sAMAccountName وuserPrincipalName لبناء قائمة مستخدمين.
البحث عن Groups KALI TERMINAL
ldapsearch -x -H ldap://[TARGET]:389 -b "[BASE_DN]" "(objectClass=group)" cn member
عضويات المجموعات قد تعطيك سياق مهم عن الحسابات ذات الصلاحيات.
Nmap LDAP Search KALI TERMINAL
nmap -Pn -p389 --script ldap-search --script-args "ldap.base='[BASE_DN]'" [TARGET]
إذا Anonymous Bind مرفوض، انتقل لاختبار Credentials مصرح بها بدل افتراض أن LDAP غير مفيد.

LDAPS / TLS

فحص شهادة LDAPS KALI TERMINAL
openssl s_client -connect [TARGET]:636 -showcerts
راجع Subject وSAN وأسماء الدومين؛ أحيانًا تساعدك في تثبيت [DOMAIN].
LDAP Search عبر TLS KALI TERMINAL
ldapsearch -x -H ldaps://[TARGET]:636 -b "[BASE_DN]" "(objectClass=*)" dn
لا تستخدم تعطيل التحقق من TLS كحل دائم؛ في اللاب فقط عالج مشاكل الشهادة بما يناسب البيئة.

4. Credential Testing

اختبر بيانات الدخول داخل النطاق المصرح فقط، وابدأ بمحاولة Bind مباشرة قبل أي Password Attack.

Bind بحساب معروف KALI TERMINAL
ldapwhoami -x -H ldap://[TARGET]:389 -D "[BIND_DN]" -w "[PASSWORD]"
نجاح Bind يؤكد أن الـDN وكلمة المرور صالحان، وبعدها استخدمهما في ldapsearch.
GENERAL REFERENCE — النجاح = قبول الـbind للحساب المحدد.
Authenticated LDAP Search KALI TERMINAL
ldapsearch -x -H ldap://[TARGET]:389 -D "[BIND_DN]" -w "[PASSWORD]" -b "[BASE_DN]" "(objectClass=*)" dn
الحساب الموثق قد يرى Objects وAttributes أكثر من Anonymous Bind.
GENERAL REFERENCE — النجاح = رجوع directory objects ضمن صلاحيات الحساب المقبول.
Password Testing عبر Hydra KALI TERMINAL
hydra -L [USERLIST] -P [WORDLIST] ldap2://[TARGET]
Password spraying/brute force قد يسبب Account Lockout. استخدمه فقط داخل Lab أو عندما يكون مصرحًا صراحة.
البحث عن LDAP modules في Metasploit MSFCONSOLE
search type:auxiliary ldap
أسماء Modules تختلف حسب إصدار Metasploit. اعرض النتائج أولًا ثم اختر Scanner/Login module المناسب بدل الاعتماد على اسم Module قديم.
مراجعة خيارات الـModule قبل التشغيل MSFCONSOLE
info [LDAP_MODULE] use [LDAP_MODULE] show options
اضبط RHOSTS/RPORT وCredentials حسب الخيارات التي يعرضها إصدارك، ثم شغّل فقط Scanner المناسب للـLab.

5. Directory Access / Permission Assessment

في LDAP غالبًا المسار العملي هو استغلال Misconfiguration أو صلاحيات قراءة زائدة، وليس تشغيل Exploit عشوائي.

تأكد من الخدمة والإصدار والنظام والـPreconditions قبل أي exploit. لا تشغّل CVE أو Module لمجرد أن 389/636 مفتوح.
استخراج Attributes مفيدة بعد Anonymous/Authenticated Bind KALI TERMINAL
ldapsearch -x -H ldap://[TARGET]:389 -D "[BIND_DN]" -w "[PASSWORD]" -b "[BASE_DN]" "(objectClass=user)" sAMAccountName description memberOf
راجع description وmemberOf وأي Attributes مسموح لك بقراءتها بحثًا عن معلومات تساعد في الخطوة التالية.
تحديد الحسابات والخدمات عبر SPN attribute KALI TERMINAL
ldapsearch -x -H ldap://[TARGET]:389 -D "[BIND_DN]" -w "[PASSWORD]" -b "[BASE_DN]" "(servicePrincipalName=*)" sAMAccountName servicePrincipalName
هذا Enumeration فقط. أي Kerberos workflow لاحق يُراجع في ملف Kerberos بدل تكراره هنا.
البحث عن Computers KALI TERMINAL
ldapsearch -x -H ldap://[TARGET]:389 -D "[BIND_DN]" -w "[PASSWORD]" -b "[BASE_DN]" "(objectClass=computer)" dNSHostName operatingSystem operatingSystemVersion
يعطيك خريطة أفضل للأجهزة والأنظمة الظاهرة للدليل.
مراجعة ACL/AD data بأداة مخصصة عند توفر Credentials KALI TERMINAL
bloodhound-python -u [USERNAME] -p '[PASSWORD]' -d [DOMAIN] -ns [DNS_IP] -c All
هذا جمع بيانات Active Directory وقد يكون noisy. شغّله فقط داخل نطاق Lab/اختبار مصرح.
إذا LDAP أعطاك Domain/User/Group/Hostnames فقط، فهذا نجاح مهم في الـEnumeration. لا يلزم أن تنتج الخدمة Shell مباشرة.

6. Findings / Handoff

ثبّت المعلومات التي حصلت عليها من LDAP وحوّلها لمدخلات للخدمات التالية بدون تكرار Post-Exploitation العام.

حفظ أسماء المستخدمين بشكل مرتب KALI TERMINAL
ldapsearch -LLL -x -H ldap://[TARGET]:389 -D "[BIND_DN]" -w "[PASSWORD]" -b "[BASE_DN]" "(objectClass=user)" sAMAccountName | awk '/^sAMAccountName:/{print $2}' | sort -u > ldap_users.txt
استخدم القائمة لاحقًا فقط ضمن اختبارات Authentication المصرح بها.
حفظ أسماء الأجهزة KALI TERMINAL
ldapsearch -LLL -x -H ldap://[TARGET]:389 -D "[BIND_DN]" -w "[PASSWORD]" -b "[BASE_DN]" "(objectClass=computer)" dNSHostName | awk '/^dNSHostName:/{print $2}' | sort -u > ldap_hosts.txt
هذه القائمة تساعدك في ربط LDAP مع DNS/SMB/Kerberos وباقي الخدمات.
تأكيد الـBase DN والـDomain قبل الانتقال KALI TERMINAL
ldapsearch -LLL -x -H ldap://[TARGET]:389 -s base -b "" defaultNamingContext namingContexts
سجّل [DOMAIN] و[BASE_DN] والحسابات والمجموعات والأجهزة المهمة، ثم انتقل للخدمة المرتبطة بدل إعادة Enumeration من الصفر.
