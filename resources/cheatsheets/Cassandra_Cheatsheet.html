PORT 9042 / TCP — APACHE CASSANDRA / CQL

Cassandra — من الفحص إلى تقييم صلاحيات CQL

Quick Service Reference — مرجع عملي للـLab: اكتشاف Cassandra، Enumeration للـCluster والـKeyspaces، اختبار المصادقة، ثم تقييم الوصول بدون تغيير البيانات.

1. Reconnaissance

ثبّت الهدف ومسار الشبكة قبل فحص Cassandra.

معرفة عنوانك ومسار الشبكة KALI TERMINAL
ip a ip route
حدد واجهة الـLab/VPN قبل فحص الخدمة.
اختبار الوصول للهدف KALI TERMINAL
ping -c 4 [TARGET]
فشل ICMP لا يعني أن Cassandra غير متاحة؛ استخدم -Pn في Nmap.
اكتشاف الأجهزة عند الحاجة KALI TERMINAL
nmap -sn [SUBNET]

2. Port Scanning

أكد Native Transport والإصدار وابحث عن البورتات غير القياسية عند الحاجة.

فحص Native Transport الافتراضي KALI TERMINAL
nmap -Pn -p9042 -sV [TARGET]
9042/TCP هو المنفذ الشائع لاتصالات CQL الحديثة.
GENERAL REFERENCE — النجاح = Nmap يعرّف Cassandra/CQL أو يؤكد الخدمة المتوقعة على البورت.
Default Scripts + Version Detection KALI TERMINAL
nmap -Pn -p9042 -sC -sV [TARGET]
فحص منافذ Cassandra القديمة/الإدارية المحتملة KALI TERMINAL
nmap -Pn -p7000,7001,7199,9042,9160 -sV [TARGET]
وجود أحد هذه المنافذ لا يثبت وحده إمكانية الدخول؛ اربطه بالإصدار والـconfiguration.
فحص TCP شامل إذا لم تظهر الخدمة KALI TERMINAL
nmap -Pn -p- --min-rate 1000 [TARGET]
استخدم معدل الفحص المناسب فقط داخل Lab أو حسب قواعد الاختبار المصرح.
إعادة فحص البورت المكتشف KALI TERMINAL
nmap -Pn -p[PORT] -sC -sV [TARGET]

3. Enumeration

ابدأ بالـmetadata: cluster، version، keyspaces، ثم schema المسموح لك برؤيته.

CQL / Cluster Enumeration

الاتصال عبر cqlsh بدون Credentials KALI TERMINAL
cqlsh [TARGET] [PORT]
إذا سمحت البيئة بالاتصال ستدخل إلى CQL shell؛ إذا طلبت/رفضت المصادقة انتقل لمسار Credentials.
GENERAL REFERENCE — إذا سمح cqlsh بالاستعلام بدون credentials فهذا وصول غير موثق؛ قيّم ما يمكن قراءته أو تعديله.
عرض نسخة CQL/Server من داخل الجلسة CQLSH
SHOW VERSION
سجّل النسخة التي يعرضها الخادم بدل افتراض إصدار معين.
عرض الـCluster CQLSH
DESCRIBE CLUSTER
يعرض معلومات عن الـcluster عندما تسمح الصلاحيات.
عرض Keyspaces CQLSH
DESCRIBE KEYSPACES
ابدأ بالـmetadata فقط قبل قراءة أي بيانات.
GENERAL REFERENCE — النجاح = ظهور Keyspaces المتاحة للسياق الحالي.
استعراض Keyspace معروف CQLSH
DESCRIBE KEYSPACE [KEYSPACE]
استخدم اسمًا ظهر فعليًا من DESCRIBE KEYSPACES.
عرض معلومات النظام بشكل محدود CQLSH
SELECT cluster_name, data_center, rack, release_version FROM system.local;
قراءة metadata تساعد على فهم الـnode والإصدار بدون تغيير البيانات.
لا توجد هنا نتيجة Lab أو Expected Output ثابتة لـCassandra؛ لذلك لا تعتبر أي اسم Cluster/Keyspace أو Version نتيجة متوقعة حتى يظهر فعليًا.

4. Credential Testing

حدد هل Authentication مفعلة، ثم استخدم بيانات دخول مصرح بها فقط.

الدخول ببيانات معروفة KALI TERMINAL
cqlsh [TARGET] [PORT] -u [USERNAME] -p [PASSWORD]
استخدم Credentials حصلت عليها من اللاب أو من مسار مصرح.
GENERAL REFERENCE — النجاح = قبول credentials وفتح CQL session تسمح بالاستعلام ضمن صلاحيات الحساب.
التحقق من المستخدم الحالي CQLSH
LIST USERS;
قد يحتاج هذا الأمر صلاحيات مناسبة؛ الرفض لا يعني فشل تسجيل الدخول.
البحث عن Scanner مناسب في Metasploit MSFCONSOLE
search cassandra search cql search type:auxiliary cassandra
لا تعتمد على اسم Module محفوظ إذا لم يكن موجودًا في إصدار Metasploit عندك؛ استخدم info/show options للنتيجة الفعلية.
تنبيه: لا تبدأ Password Spraying أو Brute Force لمجرد أن 9042 مفتوح. تأكد أولًا أن Password Authentication مفعلة وأن الاختبار مسموح ضمن اللاب.

5. Authorization / Data Access Assessment

ركز على Misconfiguration والصلاحيات الزائدة؛ لا تضف CVE أو تغيّر البيانات بدون Preconditions واضحة.

Misconfiguration / Excessive Access

اختبار صلاحيات المستخدم الحالي CQLSH
LIST ALL PERMISSIONS;
إذا كانت الصلاحيات تسمح، استخدم الناتج لتحديد هل الحساب يملك وصولًا أوسع من المطلوب.
GENERAL REFERENCE — استخدم الصلاحيات الظاهرة لتحديد ما إذا كان الوصول قراءة فقط أم يسمح بتغييرات.
قراءة عينة محدودة من جدول معروف CQLSH
SELECT * FROM [KEYSPACE].[TABLE] LIMIT 5;
نفّذها فقط على جدول ظهر فعليًا في Enumeration وضمن نطاق اللاب؛ LIMIT يقلل القراءة غير الضرورية.
فحص Modules المناسبة للإصدار MSFCONSOLE
search cassandra info [MODULE] show options
لا تشغّل Exploit قبل مطابقة Service/Version/OS/Preconditions. لا توجد هنا نتيجة Cassandra exploit ناجحة ثابتة.
لا تستخدم DROP / TRUNCATE / DELETE / INSERT / UPDATE أو تغييرات Schema لمجرد الاختبار؛ هذه أوامر تغيّر البيانات وقد تعطل التطبيق.

6. Documentation / Handoff

وثّق ما أثبتته واربط قاعدة البيانات بالتطبيق والخدمات الأخرى بدون تغييرات تخريبية.

توثيق Schema بدون تغيير البيانات CQLSH
DESCRIBE KEYSPACES DESCRIBE KEYSPACE [KEYSPACE]
احتفظ بالـmetadata التي تحتاجها للـLab فقط.
حفظ معلومات الخدمة محليًا KALI TERMINAL
nmap -Pn -p[PORT] -sV [TARGET] -oN cassandra_service.txt
يحفظ Evidence محليًا بدون تعديل Cassandra.
ربط Cassandra بالخدمات الأخرى KALI TERMINAL
nmap -Pn -sV [TARGET]
بعد إثبات Cassandra، اربط الـkeyspaces والتطبيقات بالخدمات الأخرى على نفس الهدف بدل التعامل معها بمعزل.
إذا حصلت لاحقًا على Shell من خدمة أخرى، راجع إعدادات Cassandra والـcredentials محليًا ضمن Post-Exploitation العام بدل تكرار أوامر النظام هنا.
