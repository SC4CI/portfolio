PORT 110 / 995 — POP3 / POP3S

POP3 — من اكتشاف الخدمة إلى قراءة البريد

مرجع سريع أثناء اللاب — Banner، Capabilities، Authentication، Mail Retrieval، واستخراج المعلومات المفيدة

ملاحظة عن البورت: POP3 يعمل عادة على 110/TCP، بينما POP3S المشفر يعمل على 995/TCP. قد يستخدم الخادم STARTTLS على 110 بدل الاعتماد على 995.

1. Reconnaissance

حدد هل الهدف يشغل خدمة بريد POP3 عادية أو مشفرة قبل بدء الاختبار.

معرفة الشبكة والهدف KALI TERMINAL
ip a ip route
فحص خدمات البريد الشائعة KALI TERMINAL
nmap -Pn -sV -p25,110,143,465,587,993,995 [TARGET]
وجود SMTP مع POP3/IMAP يساعدك تربط workflow البريد كامل.
POP3 يستخدم غالبًا 110/TCP، وPOP3S المشفر يستخدم 995/TCP. بعد تسجيل الدخول يكون الهدف عادة قراءة الرسائل وليس الحصول على shell مباشرة.

2. Port Scanning

أكد الخدمة والإصدار وما إذا كانت TLS مطلوبة.

فحص POP3 KALI TERMINAL
nmap -Pn -sV -p110,995 [TARGET]
✓ ظهور pop3 أو pop3s يؤكد أن الخدمة متاحة.
فحص سكربتات POP3 KALI TERMINAL
nmap -Pn -p110,995 --script=pop3-capabilities,pop3-ntlm-info [TARGET]
قد يكشف capabilities أو معلومات NTLM في بعض البيئات.
فحص SSL على 995 KALI TERMINAL
nmap -Pn -sV --script=ssl-cert,ssl-enum-ciphers -p995 [TARGET]
استخدمه إذا كانت الخدمة POP3S.

3. Enumeration

اجمع banner وcapabilities، ثم استخدم أي usernames حصلت عليها من SMTP أو SMB أو LDAP أو مصادر أخرى.

قراءة Banner يدويًا KALI TERMINAL
nc -nv [TARGET] 110
ابحث عن اسم المنتج أو إصدار الخدمة.
✓ استجابة تبدأ عادة بـ +OK تعني أن خادم POP3 يرد.
عرض Capabilities POP3 CLIENT
CAPA
إذا كانت الخدمة تسمح بذلك، قد ترى USER أو SASL أو STLS أو UIDL وغيرها.
POP3S عبر OpenSSL KALI TERMINAL
openssl s_client -connect [TARGET]:995 -crlf
بعد الاتصال يمكنك كتابة أوامر POP3 يدويًا داخل الجلسة.
STARTTLS على 110 عند دعمه KALI TERMINAL
openssl s_client -connect [TARGET]:110 -starttls pop3 -crlf
يفيد إذا أعلن الخادم STLS.
POP3 ليس دائمًا مناسبًا لـUser Enumeration مستقل. الأفضل غالبًا استخدام usernames اكتشفتها من SMTP/SMB/LDAP ثم اختبارها هنا.

4. Credential Testing

اختبر بيانات الاعتماد المعروفة أولًا، ثم استخدم password spraying أو أدوات مناسبة داخل بيئة مصرح بها.

تسجيل دخول يدوي POP3 CLIENT
USER [USERNAME] PASS [PASSWORD]
تجربة مفيدة للتأكد من credential واحد.
✓ +OK Logged in أو استجابة مشابهة = المصادقة نجحت.
Hydra على POP3 KALI TERMINAL
hydra -L [USERLIST] -P [WORDLIST] pop3://[TARGET]
استخدمه فقط داخل Lab وبوعي بسياسة lockout.
Hydra على POP3S KALI TERMINAL
hydra -L [USERLIST] -P [WORDLIST] pop3s://[TARGET]
Metasploit POP3 Login MSFCONSOLE
use auxiliary/scanner/pop3/pop3_login set RHOSTS [TARGET] set USER_FILE [USERLIST] set PASS_FILE [WORDLIST] run
مسار بديل لاختبار تسجيل الدخول.
تحذير: اختبارات كلمات المرور قد تسبب Account Lockout. ابدأ بالـcredentials المعروفة أو Password Spraying منخفض المعدل.

5. Mailbox Access

في POP3 الاستغلال العملي غالبًا هو الوصول لصندوق البريد واستخراج معلومات مفيدة، وليس CVE عشوائي.

عرض عدد الرسائل POP3 CLIENT
STAT
يعرض عدد الرسائل والحجم الإجمالي تقريبًا.
عرض قائمة الرسائل POP3 CLIENT
LIST
يعرض أرقام الرسائل وأحجامها.
قراءة رسالة محددة POP3 CLIENT
RETR [MESSAGE_NUMBER]
ابحث عن credentials، روابط reset، hostnames، internal IPs أو معلومات تشغيلية مهمة.
عرض Unique IDs POP3 CLIENT
UIDL
يساعد في تمييز الرسائل عند الحاجة.
إنهاء الجلسة POP3 CLIENT
QUIT
إذا وجدت Credentials في البريد، اختبر إعادة استخدامها على SSH/SMB/WinRM/RDP/Web فقط إذا كانت هذه الخدمات ضمن نطاق اللاب المصرح.

6. Findings / Handoff

حوّل محتوى البريد إلى leads واضحة للخدمات التالية بدل التوسع في Post-Exploitation عام.

البحث في رسائل محفوظة محليًا KALI TERMINAL
grep -RniE 'pass|password|user|token|key|host|vpn|ssh|rdp|http' [MAIL_DIR_OR_FILE]
ركز على المعلومات التي تقودك لخطوة منطقية تالية.
فحص بورت مكتشف من البريد KALI TERMINAL
nmap -Pn -sV -p[DISCOVERED_PORT] [TARGET_OR_HOST]
اختبار Credential مكتشف على خدمة أخرى KALI TERMINAL
nmap -Pn -sV -p22,445,3389,5985,5986 [TARGET]
حدد أولًا الخدمات المفتوحة، ثم استخدم الـCheatsheet المناسب بدل إعادة كل workflow هنا.
POP3 غالبًا مصدر معلومات. إذا حصلت على Credential أو Host داخلي أو URL، انتقل إلى Sheet الخدمة المقابلة.
