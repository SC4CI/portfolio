IMAP — من اكتشاف الخدمة إلى قراءة البريد والمجلدات

مرجع سريع أثناء اللاب — Banner، Capabilities، Authentication، Mailbox Enumeration، وقراءة الرسائل

1. Reconnaissance

حدد هل الهدف يشغل IMAP عادي أو IMAPS، واربطه بباقي خدمات البريد.

معرفة الشبكة والهدف KALI TERMINAL
ip a ip route
فحص خدمات البريد الشائعة KALI TERMINAL
nmap -Pn -sV -p25,110,143,465,587,993,995 [TARGET]
وجود SMTP مع IMAP/POP3 يساعدك تفهم بنية خدمة البريد كاملة.
IMAP يستخدم غالبًا 143/TCP، بينما IMAPS المشفر يستخدم 993/TCP. بخلاف POP3، IMAP مصمم لإدارة الرسائل والمجلدات مباشرة على الخادم.

2. Port Scanning

أكد الخدمة والإصدار، ثم افحص TLS والـcapabilities المتاحة.

فحص IMAP / IMAPS KALI TERMINAL
nmap -Pn -sV -p143,993 [TARGET]
✓ ظهور imap أو imaps يؤكد أن الخدمة متاحة.
فحص شامل إذا كانت الخدمة على بورت مختلف KALI TERMINAL
nmap -Pn -p- --min-rate 1000 [TARGET]
إذا ظهر IMAP على بورت غير 143/993، استخدم البورت الفعلي في خطوات enumeration والاتصال.
فحص Capabilities عبر Nmap KALI TERMINAL
nmap -Pn -p143,993 --script=imap-capabilities [TARGET]
قد يكشف AUTH methods وSTARTTLS وIDLE وغيرها.
فحص SSL على 993 KALI TERMINAL
nmap -Pn -sV --script=ssl-cert,ssl-enum-ciphers -p993 [TARGET]
استخدمه إذا كانت الخدمة IMAPS.

3. Enumeration

اجمع banner وcapabilities، ثم استخدم أي usernames اكتشفتها من SMTP/SMB/LDAP أو مصادر أخرى.

قراءة Banner يدويًا KALI TERMINAL
nc -nv [TARGET] 143
ابحث عن اسم المنتج أو أي معلومات من banner.
✓ استجابة تبدأ عادة بـ * OK تعني أن خادم IMAP يرد.
عرض Capabilities IMAP CLIENT
a1 CAPABILITY
IMAP يحتاج tag مثل a1 في بداية كل أمر.
IMAPS عبر OpenSSL KALI TERMINAL
openssl s_client -connect [TARGET]:993 -crlf
بعد الاتصال يمكنك إرسال أوامر IMAP يدويًا.
STARTTLS على 143 KALI TERMINAL
openssl s_client -connect [TARGET]:143 -starttls imap -crlf
استخدمه إذا كانت الخدمة تدعم STARTTLS.
احتفظ بالـDomain/Usernames التي وجدتها من خدمات ثانية؛ IMAP غالبًا ليس أفضل مكان لاكتشاف المستخدمين من الصفر.

4. Credential Testing

ابدأ ببيانات اعتماد معروفة، ثم استخدم Password Spraying أو أدوات مخصصة بحذر.

تسجيل دخول يدوي IMAP CLIENT
a1 LOGIN [USERNAME] [PASSWORD]
يفيد للتحقق من credential واحد.
✓ a1 OK LOGIN completed أو استجابة مشابهة = الدخول نجح.
Hydra على IMAP KALI TERMINAL
hydra -L [USERLIST] -P [WORDLIST] imap://[TARGET]
استخدمه فقط داخل Lab وبوعي بسياسة lockout.
Hydra على IMAPS KALI TERMINAL
hydra -L [USERLIST] -P [WORDLIST] imaps://[TARGET]
Metasploit IMAP Login MSFCONSOLE
use auxiliary/scanner/imap/imap_login set RHOSTS [TARGET] set USER_FILE [USERLIST] set PASS_FILE [WORDLIST] run
مسار بديل لاختبار المصادقة.
تحذير: اختبارات كلمات المرور قد تسبب Account Lockout. إذا عندك credential معروف اختبره أولًا بدل brute force.

5. Mailbox Access

الاستغلال العملي هنا يعني قراءة البريد والمجلدات واستخراج معلومات تقودك لخدمات أخرى.

تنبيه: لا تضف أو تشغّل Exploit عشوائي على IMAP. إذا ظهر إصدار محدد وثغرة موثقة فعلًا، تأكد من الإصدار والنظام والشروط قبل أي exploit. هنا المسار الأساسي هو الاستفادة من وصول مصادق عليه للـMailbox.
عرض Mailboxes IMAP CLIENT
a2 LIST "" "*"
يعرض INBOX والمجلدات المتاحة.
اختيار INBOX IMAP CLIENT
a3 SELECT INBOX
يعرض معلومات عن الصندوق وعدد الرسائل.
البحث عن كل الرسائل IMAP CLIENT
a4 SEARCH ALL
يرجع أرقام الرسائل المتاحة.
قراءة رسالة محددة IMAP CLIENT
a5 FETCH [MESSAGE_NUMBER] BODY[]
اقرأ المحتوى وابحث عن credentials، reset links، hosts، IPs أو معلومات تشغيلية مهمة.
قراءة Headers فقط IMAP CLIENT
a6 FETCH [MESSAGE_NUMBER] BODY[HEADER]
مفيد لتتبع From/To/Subject بدون سحب كامل الرسالة.
إنهاء الجلسة IMAP CLIENT
a7 LOGOUT
إذا وجدت Credentials أو Hostnames داخل الرسائل، انتقل للـSheet الخاص بالخدمة المرتبطة بدل توسيع ملف IMAP.

6. Findings / Handoff

حوّل البريد المكتشف إلى leads واضحة ثم انتقل للخدمة المناسبة.

البحث داخل رسائل محفوظة KALI TERMINAL
grep -RniE 'pass|password|user|token|key|host|vpn|ssh|rdp|http' [MAIL_DIR_OR_FILE]
ركز على الأشياء التي تقود مباشرة لخطوة تالية.
فحص بورت أو Host مكتشف KALI TERMINAL
nmap -Pn -sV -p[DISCOVERED_PORT] [TARGET_OR_HOST]
اختبار الخدمات الشائعة بعد اكتشاف Credentials KALI TERMINAL
nmap -Pn -sV -p22,445,3389,5985,5986 [TARGET]
حدد أولًا ما هو مفتوح ثم استخدم الـCheatsheet المناسب.
IMAP غالبًا يعطيك معلومات وليس Shell. إذا حصلت على Credential صالح، انتقل إلى SSH/SMB/WinRM/RDP/Web حسب الخدمات المفتوحة.
