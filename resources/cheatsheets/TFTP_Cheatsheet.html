PORT 69 / UDP — TFTP

TFTP — من الفحص إلى استغلال صلاحيات الملفات

مرجع سريع أثناء اللاب — اكتشاف الخدمة، GET/PUT، Read/Write Access، والانتقال للخدمة التالية

1. Reconnaissance

تعرف على الهدف والشبكة قبل فحص TFTP.

معرفة عنوانك ومسار الشبكة KALI TERMINAL
ip a ip route
حدد الواجهة التي تصل منها إلى الهدف، خصوصًا واجهة VPN أثناء اللابات.
اختبار الوصول المبدئي KALI TERMINAL
ping -c 4 [TARGET]
عدم الرد لا يعني أن الجهاز مغلق؛ TFTP يعمل غالبًا عبر UDP لذلك انتقل للفحص حتى لو ICMP محجوب.
TFTP اختصار لـ Trivial File Transfer Protocol ويعمل غالبًا على 69/UDP. لا يستخدم Username/Password مثل FTP، وغالبًا يعتمد على مجلد مشاركة محدد وصلاحيات الخادم.

2. Port Scanning

بما أن TFTP يعمل عبر UDP، استخدم فحص UDP بدل الاكتفاء بفحص TCP.

فحص بورت TFTP KALI TERMINAL
sudo nmap -sU -p69 [TARGET]
✓ ظهور 69/udp open tftp أو open|filtered يعني أن الخدمة تستحق Enumeration إضافي.
Service Detection KALI TERMINAL
sudo nmap -sU -sV -p69 [TARGET]
يحاول Nmap تحديد أن الخدمة TFTP وربما تنفيذ probes مناسبة.
فحص UDP أوسع عند الحاجة KALI TERMINAL
sudo nmap -sU --top-ports 50 [TARGET]
مفيد إذا كان الهدف يقدم أكثر من خدمة UDP بجانب TFTP.
مهم: UDP أبطأ وأقل وضوحًا من TCP. نتيجة open|filtered لا تؤكد أن TFTP يعمل، لذلك أكمل باختبار العميل.

3. Enumeration

TFTP لا يوفر Directory Listing قياسيًا، لذلك Enumeration يعتمد غالبًا على معرفة أو تخمين أسماء الملفات.

فتح عميل TFTP KALI TERMINAL
tftp [TARGET]
إذا ظهر لك prompt مثل tftp> فأنت داخل العميل المحلي ومستعد لتجربة GET/PUT.
تفعيل الوضع verbose TFTP CLIENT
verbose
يساعدك في رؤية تفاصيل أوضح أثناء النقل.
تجربة ملف معروف TFTP CLIENT
get [KNOWN_FILE]
ابدأ بأسماء ملفات مرتبطة بسياق اللاب أو الخدمة، ولا تعتمد على التخمين العشوائي.
✓ Transfer successful أو نزول الملف محليًا = Read Access مؤكد.
محاولة تنزيل عبر atftp KALI TERMINAL
atftp --get --remote-file [KNOWN_FILE] --local-file [LOCAL_FILE] [TARGET]
طريقة بديلة مباشرة بدون جلسة تفاعلية.
لأن TFTP عادة لا يدعم LIST، نجاحك يعتمد كثيرًا على أسماء ملفات متوقعة أو معلومات وجدتها من خدمة أخرى مثل Web/SMB/SNMP.

4. Read / Write Access Testing

TFTP التقليدي لا يملك Username/Password. الاختبار هنا يكون على صلاحيات القراءة والكتابة بدل Brute Force.

اختبار Read Access TFTP CLIENT
get [KNOWN_FILE]
إذا نجح النقل فأنت قادر على قراءة الملف من مجلد TFTP.
إنشاء ملف اختبار محلي KALI TERMINAL
echo 'tftp-test' > tftp_test.txt
اختبار Write Access TFTP CLIENT
put tftp_test.txt
اختبر فقط داخل بيئة Lab مصرح بها وبملف جديد غير مؤذٍ.
✓ Successful transfer = الخادم يسمح بالكتابة إلى TFTP root أو المسار المسموح.
اختبار Upload عبر atftp KALI TERMINAL
atftp --put --local-file tftp_test.txt --remote-file tftp_test.txt [TARGET]
بديل سريع لاختبار الكتابة.
لا تستخدم Hydra أو Password Lists مع TFTP لمجرد وجود مرحلة Credential Testing؛ البروتوكول نفسه لا يطبق Authentication تقليديًا.

5. File Retrieval / Upload Abuse

استغلال TFTP غالبًا يعني الاستفادة من Read/Write Access أو من ملفات حساسة مكشوفة، وليس CVE عشوائي.

تنزيل ملف حساس معروف TFTP CLIENT
get [SENSITIVE_OR_CONFIG_FILE]
ركز على ملفات إعدادات أو نسخ احتياطية أو ملفات مرتبطة بخدمة أخرى ظهرت في اللاب.
فحص الملف بعد تنزيله KALI TERMINAL
file [DOWNLOADED_FILE] cat [DOWNLOADED_FILE]
حدد نوع الملف ثم اقرأه فقط إذا كان نصيًا ومسموحًا لك تحليله.
البحث عن معلومات مفيدة داخل الملف KALI TERMINAL
grep -RniE 'user|pass|secret|key|token|host|port' [DOWNLOADED_FILE_OR_DIR]
استخدم النتائج كـleads لخدمات أخرى بدل اعتبار TFTP نهاية المسار.
التحقق من ملف تم رفعه TFTP CLIENT
get tftp_test.txt
إذا رفعت ملف اختبار، نزّله للتأكد أن الكتابة فعلًا تمت وأنك تتعامل مع نفس TFTP root.
إذا وجدت Credentials أو Config لخدمة ثانية مثل SSH/HTTP/Database، انتقل للـSheet الخاص بتلك الخدمة. TFTP غالبًا يكون بوابة للحصول على معلومة، وليس Shell بحد ذاته.

6. Post-Access Verification

بعد إثبات الوصول، رتب ما حصلت عليه وحدد الخدمة التالية ثم نظف ملفات الاختبار التي أنشأتها إن أمكن.

مراجعة الملفات التي تم تنزيلها KALI TERMINAL
ls -lah sha256sum [DOWNLOADED_FILE]
وثق محليًا ما نزلته أثناء اللاب وتأكد من الملف الذي تعمل عليه.
اختبار خدمة مرتبطة بالمعلومات المكتشفة KALI TERMINAL
nmap -sV -p[DISCOVERED_PORT] [TARGET]
إذا كشف الملف Port أو Service أخرى، تحقق منها قبل الانتقال للاستغلال.
إزالة ملف الاختبار إن كان الخادم يدعم ذلك KALI TERMINAL
rm -f tftp_test.txt
هذا يحذف النسخة المحلية فقط. TFTP التقليدي لا يملك أمر DELETE قياسيًا من العميل.
لا تكرر Post-Exploitation العام هنا. إذا حصلت على Credentials أو Shell، انتقل إلى Credential Access أو Linux/Windows Post-Exploitation حسب الحالة.
