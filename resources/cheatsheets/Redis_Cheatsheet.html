Redis — من الفحص إلى ما بعد الاستغلال

Quick Service Reference — مرجع عملي سريع للـLab: اكتشاف Redis، Enumeration، Authentication، قراءة البيانات المسموحة، ثم تحويل النتائج للخطوة التالية.

1. Reconnaissance

ثبّت عنوانك والهدف ومسار الشبكة قبل فحص Redis.

معرفة عنوان جهازك ومسار الشبكة KALI TERMINAL
ip a ip route
اختبار الوصول للهدف KALI TERMINAL
ping -c 4 [TARGET]
إذا لم يرد ICMP، لا تستبعد الهدف؛ استخدم -Pn في Nmap.
اكتشاف الأجهزة إذا كان لديك Subnet فقط KALI TERMINAL
nmap -sn [SUBNET]

2. Port Scanning

البورت الشائع Redis هو 6379/TCP، لكن افحص جميع البورتات إذا لم يظهر.

فحص Redis الافتراضي KALI TERMINAL
nmap -Pn -p6379 -sV [TARGET]
فحص Default Scripts والإصدار KALI TERMINAL
nmap -Pn -p6379 -sC -sV [TARGET]
فحص جميع TCP Ports KALI TERMINAL
nmap -Pn -p- --min-rate 1000 [TARGET]
استخدم معدل الفحص المناسب فقط داخل Lab أو وفق قواعد الاختبار المصرح.
إعادة فحص Redis إذا ظهر على بورت غير قياسي KALI TERMINAL
nmap -Pn -p[PORT] -sV -sC [TARGET]

3. Enumeration

حدد هل Redis يستجيب بدون Authentication، ثم استخرج معلومات الخادم وقواعد البيانات بدون تغيير البيانات.

فحص Redis عبر Nmap NSE KALI TERMINAL
nmap -Pn -p[PORT] --script redis-info [TARGET]
يعطي معلومات عن Redis إذا كانت الخدمة تسمح بالاستعلام.
اختبار PING عبر redis-cli KALI TERMINAL
redis-cli -h [TARGET] -p [PORT] PING
إذا رجع PONG فهذا يؤكد أن Redis يستجيب للأمر. إذا ظهرت NOAUTH فالمصادقة مطلوبة.
قراءة معلومات الخادم KALI TERMINAL
redis-cli -h [TARGET] -p [PORT] INFO
راجع redis_version وos وrole وconnected_clients وغيرها من المعلومات المفيدة.
عرض إعدادات مهمة بدون تعديلها KALI TERMINAL
redis-cli -h [TARGET] -p [PORT] CONFIG GET "bind" redis-cli -h [TARGET] -p [PORT] CONFIG GET "protected-mode" redis-cli -h [TARGET] -p [PORT] CONFIG GET "requirepass"
استخدم CONFIG GET فقط هنا؛ لا تغيّر إعدادات الخادم أثناء Enumeration.
عرض عدد المفاتيح في قواعد البيانات KALI TERMINAL
redis-cli -h [TARGET] -p [PORT] INFO keyspace
عرض قواعد البيانات التي تحتوي Keys KALI TERMINAL
redis-cli -h [TARGET] -p [PORT] INFO keyspace
إذا ظهر db0 أو db1 وغيرها، اختر قاعدة البيانات المناسبة قبل Enumeration أعمق.
Enumeration آمن نسبيًا للمفاتيح KALI TERMINAL
redis-cli -h [TARGET] -p [PORT] -n [DB] --scan
استخدم SCAN بدل KEYS * على قواعد البيانات الكبيرة لأنه أقل تعطيلًا.
تحديد نوع Key قبل قراءته KALI TERMINAL
redis-cli -h [TARGET] -p [PORT] TYPE [KEY]
قراءة String Key KALI TERMINAL
redis-cli -h [TARGET] -p [PORT] GET [KEY]
إذا TYPE ليس string استخدم الأمر المناسب لنوع البيانات بدل GET.

4. Credential Testing

Redis قد يعمل بدون كلمة مرور، أو يستخدم Password/ACL حسب الإصدار والإعداد.

اختبار Password معروف KALI TERMINAL
redis-cli -h [TARGET] -p [PORT] -a '[PASSWORD]' PING
PONG يعني أن المصادقة نجحت.
اختبار ACL Username + Password KALI TERMINAL
redis-cli -h [TARGET] -p [PORT] --user [USERNAME] -a '[PASSWORD]' PING
مفيد مع Redis ACL حيث توجد Users بدل الاعتماد على default user فقط.
Hydra Password Testing KALI TERMINAL
hydra -P [WORDLIST] -s [PORT] [TARGET] redis
Password attacks قد تسبب ضوضاء أو حظرًا. نفذها فقط في Lab/نطاق مصرح وبقائمة مناسبة.
البحث عن Redis Login Scanner في Metasploit MSFCONSOLE
search type:auxiliary redis login search redis
اختر الـscanner المتاح في إصدار Metasploit عندك ثم راجع خياراته قبل التشغيل.
ضبط وتشغيل Scanner المتاح MSFCONSOLE
use [REDIS_LOGIN_MODULE] show options set RHOSTS [TARGET] set RPORT [PORT] set PASS_FILE [WORDLIST] run
لا تفترض اسم Module ثابتًا إذا لم يظهر في search؛ استخدم الموجود فعليًا في إصدارك.

5. Data Access / Permission Assessment

ابدأ باستغلال ضعف الوصول نفسه: Redis مكشوف بدون Authentication أو Credentials صالحة. لا تشغّل Exploit عشوائي.

تحذير: تأكد من الإصدار والإعدادات والصلاحيات قبل أي استغلال. أوامر CONFIG SET وSAVE وكتابة الملفات تغيّر حالة الخادم وقد تسبب أثرًا تشغيليًا.
إثبات الوصول غير الموثق KALI TERMINAL
redis-cli -h [TARGET] -p [PORT] PING redis-cli -h [TARGET] -p [PORT] INFO server
إذا نفذت الأوامر الحساسة للقراءة بدون AUTH فهذا Misconfiguration مهم بحد ذاته.
قراءة Key مهم بعد تحديد نوعه KALI TERMINAL
redis-cli -h [TARGET] -p [PORT] -n [DB] TYPE [KEY] redis-cli -h [TARGET] -p [PORT] -n [DB] GET [KEY]
ابحث فقط ضمن بيانات اللاب المصرح بها عن Tokens/Credentials/Configuration قد تقود لخدمة أخرى.
فحص صلاحيات ACL للحساب الحالي KALI TERMINAL
redis-cli -h [TARGET] -p [PORT] ACL WHOAMI redis-cli -h [TARGET] -p [PORT] ACL GETUSER [USERNAME]
ACL GETUSER قد يتطلب صلاحية مناسبة. الهدف معرفة ما يسمح به الحساب قبل أي محاولة كتابة.
البحث عن Modules مرتبطة بـRedis MSFCONSOLE
search redis search [REDIS_VERSION]
طابق أي Module مع الإصدار والـpreconditions الفعلية؛ إذا لا يوجد تطابق واضح، لا تستخدم exploit.
مراجعة Module مطابق قبل التشغيل MSFCONSOLE
info [MATCHED_MODULE] show options
لا تنفذ Module حتى تتأكد أنه مناسب للنسخة والنظام والسيناريو الموجود في اللاب.

6. Findings / Handoff

حوّل المعلومات التي حصلت عليها من Redis إلى أهداف وخطوات لاحقة بدون تكرار Post-Exploitation العام.

حفظ معلومات Redis KALI TERMINAL
redis-cli -h [TARGET] -p [PORT] INFO > redis_info.txt
حفظ قائمة Keys KALI TERMINAL
redis-cli -h [TARGET] -p [PORT] -n [DB] --scan > redis_keys.txt
البحث في النتائج المحفوظة عن مؤشرات مفيدة KALI TERMINAL
grep -Eai 'pass|password|user|token|secret|key|host|url|db' redis_info.txt redis_keys.txt
هذه فلترة محلية لنتائجك؛ تحقق من كل قيمة قبل اعتبارها Credential أو Target صالحًا.
فحص خدمة جديدة اكتشفتها من Redis KALI TERMINAL
nmap -Pn -sV -p[DISCOVERED_PORT] [DISCOVERED_HOST]
إذا وجدت Host/Port/Credential يقود إلى SSH أو SMB أو قاعدة بيانات، انتقل إلى Cheatsheet الخدمة المناسبة.
