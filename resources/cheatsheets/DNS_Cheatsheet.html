1. Reconnaissance

ابدأ بالمعلومات العامة عن الدومين ثم حدد سجلاته والبنية الظاهرة قبل لمس DNS server مباشرة

WHOIS للدومين KALI TERMINAL
whois [DOMAIN]
استخدم WHOIS ضمن جمع معلومات DNS. ركّز على الـnameservers، registrar، وأي بيانات بنية تحتية مفيدة.
Lookup سريع للدومين KALI TERMINAL
host [DOMAIN]
مفيد للحصول على عنوان IP المرتبط بالدومين، وقد يعرض معلومات إضافية حسب السجلات المتاحة.
Mail Servers عبر MX KALI TERMINAL
host -t mx [DOMAIN]
استخدم هذا الأمر لاستخراج سجلات البريد المرتبطة بالدومين.
DNS Recon مبدئي KALI TERMINAL
dnsrecon -d [DOMAIN]
استخدم dnsrecon لجمع سجلات DNS ومعلومات مرتبطة بالدومين.
يمكن أيضًا استخدام dnsdumpster.com كأداة مساعدة لجمع معلومات DNS بصريًا، وليس بدل الأدوات المحلية.

2. Port Scanning

تأكد أن خدمة DNS موجودة فعلًا على الهدف وحدد هل 53/UDP و53/TCP متاحان

فحص UDP 53 KALI TERMINAL
sudo nmap -sU -p53 -sV [TARGET]
UDP هو المسار الشائع لاستعلامات DNS العادية.
فحص TCP 53 KALI TERMINAL
nmap -sT -p53 -sV [TARGET]
TCP مهم خصوصًا عند التحقق من Zone Transfer وبعض الردود الكبيرة.
فحص خدمة DNS مع NSE KALI TERMINAL
nmap -sU -p53 --script=dns-recursion [TARGET]
يفيد في التحقق هل الخادم يسمح بالـrecursive queries لجهات غير مصرح لها.
مهم: ظهور 53/UDP كـ open|filtered لا يعني أن DNS غير موجود. نفّذ استعلامًا فعليًا باستخدام host أو dig للتأكد.

3. DNS Records Enumeration

استخرج السجلات المهمة: A / AAAA / MX / NS / TXT ثم جرّب Reverse Lookup عند الحاجة

Basic Lookups

nslookup أساسي KALI TERMINAL
nslookup [DOMAIN]
A / AAAA Records عبر dig KALI TERMINAL
dig [DOMAIN] A dig [DOMAIN] AAAA
Nameservers وMail وTXT KALI TERMINAL
dig [DOMAIN] NS dig [DOMAIN] MX dig [DOMAIN] TXT
سجلات NS مهمة جدًا لأنها تعطيك أسماء خوادم DNS التي ستجرب عليها AXFR لاحقًا.

Reverse Lookup

Reverse عبر host KALI TERMINAL
host [IP]
Reverse عبر dig KALI TERMINAL
dig -x [IP]
Workflow: Domain → NS records → MX/TXT/A records → DNS server IPs → Subdomains → AXFR test.

4. Subdomain Enumeration

اجمع النطاقات الفرعية الموجودة في المصادر العامة والأدوات الحالية، ثم حوّل النتائج المؤكدة إلى Targets للفحص.

إذا كشفت سجلات DNS خدمة ثانية فيها Authentication، انتقل لملف تلك الخدمة واختبر الاعتمادات هناك.
Sublist3r KALI TERMINAL
sublist3r -d [DOMAIN]
استخدم Sublist3r لصيد النطاقات الفرعية ضمن هذا المسار.
رفع عدد الـThreads KALI TERMINAL
sublist3r -d [DOMAIN] -t 200
استخدم هذا الخيار لزيادة التوازي أثناء البحث عند الحاجة.
Subfinder KALI TERMINAL
subfinder -d [DOMAIN]
استخدم Subfinder كطريقة إضافية لحصر الـsubdomains.
Google dork للنطاقات الفرعية WEB BROWSER
site:*.[DOMAIN]
استخدم هذا البحث كطريقة Passive للعثور على subdomains مفهرسة.
يمكن أيضًا استخدام crt.sh لاكتشاف subdomains عبر شهادات TLS.

5. Zone Transfer / AXFR

ركّز على سوء إعداد مثل Zone Transfer. إذا ما ظهر exploit مرتبط بإصدار محدد، لا تشغّل استغلال عشوائي.

تحذير: تأكد من الإصدار والشروط المسبقة قبل أي exploit. نجاح AXFR يعتبر كشف معلومات بسبب سوء إعداد، وليس سببًا لإضافة CVE بلا تطابق مؤكد.
اكتشف الـNameserver أولًا KALI TERMINAL
dig [DOMAIN] NS
خذ اسم كل Nameserver وجرّب AXFR عليه بشكل منفصل.
Zone Transfer عبر host KALI TERMINAL
host -l [DOMAIN] [NAMESERVER]
استخدم هذا الشكل لاختبار Zone Transfer عبر host.
AXFR عبر dnsrecon KALI TERMINAL
dnsrecon -d [DOMAIN] -t axfr
استخدم dnsrecon مباشرة لاختبار AXFR.
AXFR عبر dig KALI TERMINAL
dig axfr @[NAMESERVER] [DOMAIN]
✓ نجاح AXFR = رجوع مجموعة سجلات الـZone بدل رفض النقل.
إذا فشل AXFR: هذا طبيعي في الخوادم المضبوطة بشكل صحيح. لا تعتبر الفشل نهاية DNS enumeration؛ أكمل records + subdomains + reverse lookups.

6. Assessment & Next Actions

حوّل نتائج DNS إلى أهداف وخدمات جديدة للفحص، بدون اختراع خطوات وصول غير موجودة.

رتّب النتائج المكتشفة KALI TERMINAL
# ركّز على: # A / AAAA -> Hosts / IPs # NS -> DNS servers # MX -> Mail servers # TXT -> معلومات وسياسات إضافية # Subdomains -> أهداف وخدمات جديدة # AXFR records -> خريطة واسعة للـZone
تحويل نتائج DNS إلى Targets للفحص KALI TERMINAL
nmap -sV [DISCOVERED_IP]
إذا كشف DNS عن host أو subdomain جديد، ارجع لمسار الفحص الطبيعي وحدد الخدمة المفتوحة قبل اختيار الـCheatsheet التالي.
الخلاصة: DNS = Information Mapping. أهم نتيجة عملية هي اكتشاف أسماء Hosts/Subdomains/Services جديدة أو Zone Transfer ناجح.
