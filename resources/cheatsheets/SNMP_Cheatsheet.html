1. Reconnaissance

حدد الشبكة والهدف قبل فحص SNMP؛ تذكّر أن الخدمة تعتمد غالبًا على UDP.

معرفة عنوانك ومسار الشبكة KALI TERMINAL
ip a ip route
راقب واجهة الشبكة أو الـVPN والمسار المؤدي إلى الهدف.
اكتشاف الأجهزة عند الحاجة KALI TERMINAL
nmap -sn [SUBNET]
هذه الخطوة لا تثبت وجود SNMP؛ هدفها فقط تحديد الأجهزة الحية المحتملة.
SNMP يستخدم غالبًا 161/UDP للاستعلامات. لأن UDP مختلف عن TCP، لا تعتمد على فحص TCP وحده.

2. Port Scanning

افحص UDP/161 بشكل مباشر ثم نفّذ فحصًا مركزًا للخدمة.

فحص SNMP على UDP/161 KALI TERMINAL
sudo nmap -sU -p161 [TARGET]
✓ ظهور 161/udp open أو open|filtered يعني أن SNMP يستحق Enumeration إضافي.
Service Detection على UDP KALI TERMINAL
sudo nmap -sU -sV -p161 [TARGET]
فحص SNMP NSE الأساسي KALI TERMINAL
sudo nmap -sU -p161 --script=snmp-info [TARGET]
إذا كانت Community String الافتراضية متاحة قد تحصل على معلومات النظام.
فحص UDP قد يكون أبطأ أو يعطي open|filtered. لا تعتبر ذلك إثباتًا نهائيًا؛ أكمل بفحص Community Strings.

3. Enumeration

بعد اكتشاف Community String صالحة، استخرج System/Users/Processes/Network/Software حسب ما يسمح به الـMIB.

Enumeration شامل عبر snmpwalk KALI TERMINAL
snmpwalk -v2c -c [COMMUNITY] [TARGET]
ابدأ من الجذر إذا كانت الـcommunity صالحة، ثم ضيّق الاستعلام إلى OIDs محددة عند الحاجة.
System Information KALI TERMINAL
snmpwalk -v2c -c [COMMUNITY] [TARGET] 1.3.6.1.2.1.1
يعرض معلومات مثل sysDescr وsysName وuptime إذا كانت متاحة.
Processes KALI TERMINAL
snmpwalk -v2c -c [COMMUNITY] [TARGET] 1.3.6.1.2.1.25.4.2.1.2
قد يكشف أسماء العمليات الجارية.
Installed Software KALI TERMINAL
snmpwalk -v2c -c [COMMUNITY] [TARGET] 1.3.6.1.2.1.25.6.3.1.2
مفيد لتحديد برامج أو مكونات تستحق فحصًا منفصلًا.
Network Interfaces KALI TERMINAL
snmpwalk -v2c -c [COMMUNITY] [TARGET] 1.3.6.1.2.1.2.2.1.2
استخرج أسماء الواجهات ثم اربطها بمعلومات IP/route المتاحة.
Enumeration عبر Metasploit MSFCONSOLE
use auxiliary/scanner/snmp/snmp_enum set RHOSTS [TARGET] set COMMUNITY [COMMUNITY] run
مسار بديل من Metasploit لجمع معلومات SNMP.
البيانات المتاحة تختلف حسب النظام والـagent والـMIB permissions؛ لا تتوقع نفس الحقول من كل جهاز.

4. Community String Testing

في SNMP v1/v2c يكون محور الاختبار هو Community String بدل Username/Password التقليدي.

اختبار Community Strings عبر onesixtyone KALI TERMINAL
onesixtyone -c [WORDLIST] [TARGET]
ابحث عن strings شائعة مثل public/private فقط داخل نطاق اللاب المصرح.
اختبار Communities عبر Nmap KALI TERMINAL
sudo nmap -sU -p161 --script=snmp-brute --script-args snmp-brute.communitiesdb=[WORDLIST] [TARGET]
اختبار عبر Metasploit MSFCONSOLE
use auxiliary/scanner/snmp/snmp_login set RHOSTS [TARGET] set PASS_FILE [WORDLIST] run
الهدف هو اكتشاف Community String صالحة، وليس اختراع credentials.
تنبيه: لا تفترض أن public أو private تعملان؛ اختبر واعتبر أي نتيجة غير موثقة مجرد احتمال حتى يؤكدها رد SNMP.

5. Information Extraction / Misconfiguration Assessment

SNMP غالبًا يعطي Information Disclosure عند ضعف Community Strings؛ لا تضف CVE عشوائيًا بدون إصدار وpreconditions.

استغلال Read Community لجمع معلومات حساسة KALI TERMINAL
snmpwalk -v2c -c [COMMUNITY] [TARGET]
إذا سمح الـagent بالقراءة الواسعة، اجمع فقط المعلومات المطلوبة لمسار اللاب ثم اربطها بالخدمات المكتشفة.
التحقق من نوع الوصول بـsnmpget KALI TERMINAL
snmpget -v2c -c [COMMUNITY] [TARGET] 1.3.6.1.2.1.1.1.0
استجابة صحيحة تؤكد أن الـcommunity صالحة للقراءة على الأقل.
فحص معلومات إضافية عبر NSE KALI TERMINAL
sudo nmap -sU -p161 --script=snmp-info,snmp-interfaces,snmp-processes [TARGET]
استخدم scripts المناسبة فقط لما تحتاجه في الـworkflow.
تحذير الاستغلال: لا تستخدم SNMP SET أو تغيّر إعدادات جهاز لمجرد أن community تبدو قابلة للكتابة. أي تعديل يحتاج تفويضًا واضحًا ومتطلبًا فعليًا في اللاب.

6. Post-Access Verification

SNMP لا يعطي Shell عادة؛ الخطوة التالية هي تحويل المعلومات المكتشفة إلى أهداف تحقق لخدمات أخرى.

حفظ System Description KALI TERMINAL
snmpget -v2c -c [COMMUNITY] [TARGET] 1.3.6.1.2.1.1.1.0
استخدم OS/device details لتحديد الـcheatsheet التالي المناسب.
استخراج Hostname KALI TERMINAL
snmpget -v2c -c [COMMUNITY] [TARGET] 1.3.6.1.2.1.1.5.0
إعادة فحص الخدمات بعد معلومات SNMP KALI TERMINAL
nmap -sV -p[PORTS_FOUND_OR_RELEVANT] [TARGET]
تحقق من الخدمات التي أشارت لها العمليات أو البرامج بدل افتراض أنها متاحة.
إذا كشفت SNMP مستخدمين أو عمليات أو شبكة داخلية، تعامل معها كـleads للتحقق. Credential Access وPivoting الكامل لهما Cheatsheets مستقلة ولا يُكرران هنا.
